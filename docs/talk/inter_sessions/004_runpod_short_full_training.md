## 背景（先に読んでほしい）

**このコンペで何をしているか。** PARC2026 の本選 1 である。ロボット（Franka Emika Panda）に
自然言語の指示を与え、LIBERO-plus のシミュレータの中で物を掴んで運ばせる。
こちらの方策は **π0.5**（PaliGemma 2B ＋ 視覚側 SigLIP ＋ 行動側 gemma_300m、
合計 **4,143,404,816** パラメータ）。`solution/policy_server.py` が画像 2 枚
（`front` と `wrist`）と状態を受け取り、行動列を返す。

**いまの立ち位置。リーダーボードは 8/28 時点でこうである。**

| トラック | 中身 | **こちらの点** | **最高点** |
|---|---|---|---|
| Track1 | 学習済みタスク・背景と照明が変わる | **0.370** | **0.65** |
| Track2 | 学習済みタスク・視点・姿勢・配置・雑音が変わる | **0.207** | **0.53** |
| Track3 | 見たことのないタスク | 0.000 | 0.000（**全参加者 0**） |

**多くの参加者が 0.4 を超えている。こちらは先頭集団の下にいる。**
Track3 は全員 0 なので投資しない（原因は
[knowledge/17](../../knowledge/17_track3_picks_the_wrong_object.md)——**違う物を掴んでいる**）。

### なぜ「学習が足りていない」と読んでいるのか

**こちらが全パラメータを学習したのは 3,000 ステップだけである。**

| 学習 | いつ | 歩数 | batch | **何を学習したか** |
|---|---|---|---|---|
| `pi05_full_runpod`（＝ `rp3000`） | 8/17 | **3,000** | 64 | **全部（4.14B）** |
| `stage3_aug` / `stage3_noaug` | 8/26 | 6,000 | 8 | 行動側だけ |
| `stage4_b16_24k` | 8/27 | 24,000 | 16 | 行動側だけ |

**8/17 以降の 30,000 歩は、画像側が 1 ビットも動いていない。**
重みを直接比べて凍結側の変化が **0.000000** であることを確認済みである。
**loss は 24,000 歩でも -1.0〜-3.3% しか動かず、手元の評価は落ちるタスクの中身まで
`rp3000` と一致した。行動側だけの学習は打ち止めである。**

**`rp3000` が見たデータ量は 0.085 エポックにすぎない**（3,000 × 64 = 192,000 サンプル、
データセット全体は約 2.26M サンプル）。**先頭集団との差は、ここだと読んでいる。**

### なぜ「短く」なのか

**フルパラメータ学習が効くという確証がまだ無い。** 直近に悪い前例が 1 つある——
**画像側を凍結したままカメラ拡張を入れた 6,000 歩は、素の重みより悪くなった**
（衝突率が 0.250 → 0.375 に増えた）。**「画像側を開ければ直る」はこちらの読みであって、
測った事実ではない。**

**9,000 歩は 25.8 時間で $46〜56 かかる。** 効くか分からないものに先にそれを払うより、
**1,500 歩（4.3 時間・$8〜9）で途中の重みを 3 個残し、上がっているか下がっているかの
傾きを見てから決める。**

### 測る物差しは用意してある

**採点式は公開されている。**

```
smooth metrics = w1*time + w2*jerk + w3*SPARC + w4*trajectory + w5*rotation   (Σw = 1)
Total Score    = (1/N) * Σ successᵢ * (1 - collision penaltyᵢ) * smooth metricsᵢ
```

**成功は掛け算の門なので、失敗した回・衝突した回はその回の点がまるごと 0 になる。**
重みと正規化の中身は非公開。**手元でこの形の点を出す道具が
`solution/tools/eval/score_composite.py` である**（重みは 5 等分、
正規化は `基準値 /（基準値 + 実測）`）。

**比べる相手の数値。`rp3000` を 72 行 216 本で測った 8/28 の実測である。**

| | 値 |
|---|---|
| **合計点** | **0.3674** |
| 成功率 | 0.7222 |
| 衝突率 | 0.2269 |
| 全部成功したときの上限 | 0.4988（予選の実測 0.48 とよく合う） |

**ばらつきの目安。216 本での成功率の標準誤差はおよそ 0.031 なので、
合計点で 0.04 未満の差は「動いた」と言えない。**

### HF への上げ方

**上げるのは `pretrained_model` だけでよい**（8.8 GB）。25 GB の
`training_state` は評価に要らない。

**送り先を歩数ごとに分けること。** `hf upload` の 3 番目の引数はリポジトリ内の置き場所で、
**`.` にすると 3 つが同じ場所へ上がって上書きし合う。**

```bash
# ログを先に上げる（45 KB。重みより先）

# **単一ファイルは `path_in_repo` にファイル名が要る。**`.` はディレクトリを上げるときの形で、
# ファイルに `.` を渡すと `Invalid `path_in_repo` in CommitOperation: '.'` で落ちる（2026-08-28）

# 重みは歩数の名前のディレクトリへ

  /workspace/out/pi05_trial1500/checkpoints/000500/pretrained_model 000500 --private
```

**Xet の重複排除が効くので、2 個目・3 個目は速い**（ほぼ同じ中身のとき、
9.38 GB の上げ直しが 30 秒で終わった実測がある）。

## やること

1. **Pod を作る。** イメージは **`sirukufarios/parc2026-train-pi05:v2`**（`:v1` は使えない）。
   **Container Start Command に `bash /opt/pi05/runpod_ssh_start.sh` を入れる**——
   空にすると起動を延々と繰り返して SSH でも入れなくなる
   （[../../knowledge/13_runpod_operations.md](../../knowledge/13_runpod_operations.md) ⑥）。

2. **`experiments/` と現在の `train_pi05.py` を転送し、`--camera-viewpoint-augment` が
   あることを確かめる**（上のコマンド 2 本）。**転送しても 0 のままなら、そこで止めて
   報告すること。**`/workspace` の古い版で回してはいけない。

3. **初期重みを取り、`config.json` と `model.safetensors` が root にあることを確かめる。**

   ```bash
   hf auth login    # 先にこれ。read 権限のトークンを貼る
   hf download siruku6/pi05_full_runpod --local-dir /workspace/rp3000
   ls /workspace/rp3000/config.json /workspace/rp3000/model.safetensors
   ```

   **`hf auth login` を飛ばすと `Error: Model 'siruku6/pi05_full_runpod' not found.` になる**
   （2026-08-28 に踏んだ）。このリポジトリは非公開で、**HF は権限の無いアクセスに対して
   存在そのものを隠す**ので、「無い」と言われても名前の間違いではない。
   `HF_HOME=/workspace/hf_home` は Volume 上なので、**一度入れれば Pod を止めても残る。**
   同じログインが gemma ライセンス（7 節）にも効く。

   **`--init-from` に渡すディレクトリの直下にこの 2 つが要る。**
   無いと `--init-from` の検査で落ちる（1 階層浅い／深い間違いが起きやすい）。

4. **場所と CPU を数える。** `--num-workers` は `nproc` の半分か 16 の小さい方。

   ```bash
   du -sh /workspace/* | sort -h && nproc
   ```

   **`df` の空きは見ないこと**（Network Volume ではクラスタ全体の数字が出る。上の
   「ディスク」の節）。**枠の大きさは RunPod の Storage → Network Volumes で見る。**

5. **学習を始める。`tmux` の中で回すこと**（切れても続く）。

   ```bash
   tmux new -s train
   cd /workspace
   python /opt/pi05/train_pi05.py --run-name pi05_trial1500 \
       --init-from /workspace/rp3000 \
       --camera-viewpoint-augment \
       --steps 1500 --batch-size 64 --num-workers 16 \
       --learning-rate 5e-6 --save-freq 500 \
       --freeze-vision-encoder false --train-expert-only false
   ```

6. **始まって 2 分で 1 つだけ確かめる。ログの `num_learnable_params` である。**

   | 値 | 意味 |
   |---|---|
   | **4143404816** | **正しい。全部を学習している** |
   | 693422112 | **行動側だけ。2 つの `false` が効いていない。その場で止めること** |
   | 714412065 | 行動側 ＋ 幾何の融合層（今回は使わない設定なので出ない） |

   **止めた場合は、何を渡したかをそのまま報告すること。**
   4.3 時間回してから気付くのは高い。

7. **1 秒あたりのサンプル数をログから読み、終わる時刻を報告する。**
   参考値は 6.2 samples/s。**大きく違っていたら、そこで一度報告すること**
   （費用の見積もりが変わる）。

8. **500 歩ごとに `pretrained_model` を HF へ上げる。**
   **待たずに、出るたびに上げること**——Pod を落としたら消える。

9. **学習ログを HF か手元へ持ち出す。** **重みより先にログである。**
   45 KB のログが、後から「どこで平らになったか」を答える唯一の材料になる。
   `--log-file` の既定は `$OUTPUT_ROOT/<run-name>.log`。

10. **Pod を止める。** 動かしている間ずっと課金される。

## 報告

**成果物は揃った。**重み 3 つ・学習ログ・zip 3 本が HF にあり、Pod は止めた。
**測定値は [../../reference/19_weights_catalog.md](../../reference/19_weights_catalog.md)
「8/28 の RunPod 1,500 歩と、その 3 つの zip」に集約した**（zip と歩数の対応・sha256 を含む）。
ここには依頼の 5 項目だけを置く。

### 1. 確かめた 3 つ

| 何を | 結果 | どこで |
|---|---|---|
| `num_learnable_params` | **4143404816**（全部を学習している） | 開始 2 分後のログ |
| `compile_model` | **false** | `001500/pretrained_model/train_config.json` |
| `--camera-viewpoint-augment` | **転送した現在の版**（08-24 の `6ee31db` 以降）。`--help` の一致は 2 件（`usage:` 行と一覧） | イメージ `:v2` に焼き込まれた 08-13 の版には**無い**——上の「前提となる事実」を訂正した |

### 2. 速さと費用

| | 実測 | 見積り |
|---|---|---|
| 1 歩 | **10.05〜10.24 秒** | — |
| samples/s | **6.25〜6.35** | 6.2（**一致**） |
| 全体 | **4 時間 16 分 05 秒** | 4.3 時間（**一致**） |
| GPU メモリ | 49.37 GB（A100 80GB） | — |

**8/17 の 3,000 歩が 10.15 秒/step だったので、速さは同一である。**
**「速くなったぶんで歩数を増やす」という道は開いていなかった。**

### 3. loss の推移

**単発のログ行では読めない。**連続するログで 0.232〜0.247 まで揺れるので、
**10 点平均で読む**（台帳の表）。

| 歩数 | loss（10 点平均） |
|---|---|
| 約 500 | 0.2532 |
| 約 1,000 | 0.2463 |
| **1,500** | **0.2407** |

**500 → 1,500 で −4.9%。**行動側だけの 24,000 歩が −1.0〜−3.3% だったので、
**1 歩あたりの下がり方は桁違いに大きい。**

**`rp3000` の終わり（loss 0.209・grdn 0.633）とは直接比べられない。**
カメラ拡張で画像が歪むぶん loss の水準そのものが上がるので、
**同じ実行の中の傾きだけを読む。**

### 4. HF のリポジトリ名とパス
