# 008 RunPod で、効くと分かった学習を長く回す（歩数と設定の決定も含む）

> **状態: 報告済み** ／ 受け側: Claude（手順書を書いた） ／ 更新: 2026-08-29

**この依頼は「言われたとおりに回す」ものではない。歩数・保存の間隔・拡張を残すかを
受け側が決めて、その理由を報告に書いてほしい。**判断の材料は下に全部書いた。

## 背景（先に読んでほしい）

**このコンペで何をしているか。** PARC2026 の本選 1 である。ロボット（Franka Emika Panda）に
自然言語の指示を与え、LIBERO-plus のシミュレータの中で物を掴んで運ばせる。
こちらの方策は **π0.5**（PaliGemma 2B ＋ 視覚側 SigLIP ＋ 行動側 gemma_300m、
合計 **4,143,404,816** パラメータ）。`solution/policy_server.py` が画像 2 枚
（`front` と `wrist`）と状態を受け取り、行動列を返す。**提出は 1 日 1 トラック 1 回だけ。**

### いまの点（2026-08-29 の採点結果まで反映）

| トラック | 中身 | **こちらの点** | **最高点** |
|---|---|---|---|
| Track1 | 学習済みタスク・背景と照明が変わる | **0.492** | **0.65** |
| Track2 | 学習済みタスク・視点・姿勢・配置・雑音が変わる | **0.233** | **0.53** |
| Track3 | **LIBERO の既存タスクを逆順にしたもの**（運営が 8/28 に開示） | 0.000 | 0.000（**全参加者 0**） |

**公開点は 3 トラックの平均である**（`evaluate.py:202-204`）。いまは 0.242。

### この依頼が効くところ —— **フルパラメータ学習だけが、採点側で動いた**

**8/29 の提出で、重みだけを替えた比較が取れた。**

| | 4.2.0（`rp3000`・3,000 歩） | **5.0.1（`001500`）** | 差 |
|---|---|---|---|
| Track1 | 0.370 | **0.492** | **+0.122** |
| Track2 | 0.154 | **0.233** | **+0.079** |

**`001500` は `rp3000` から続けて 1,500 歩、画像側を開けて（`--freeze-vision-encoder false
--train-expert-only false`）カメラ拡張つきで回したものである。**
**推論の設定は 4.2.0 と 1 ビット違わず揃えてあるので、変数は重みだけである。**

**注意。採点は 8 エピソードなので、1 本ひっくり返ると 0.125 動く。**
Track1 の +0.122 は 1 本ぶんに相当し、**それ単独では偶然と区別できない。**
**2 つのトラックが同じ向きに動いたことが根拠である。**

**Track1 は歩数では説明が付かない。**打ち切り（300 歩）は 4.2.0 も 5.0.1 も 0 本で、
歩数の合計は 1,039 → 1,053 と**増えている。**つまり上がったのは
**衝突かなめらかさ 5 項**である。

### どのデータで測るのか —— **手元の評価は重みの判定に使えない**

**手元には 72 行 216 本の集合がある**（`compe/val/TRACK2_VAL72.csv`。
12 タスク × 6 条件＝素・カメラ 2 通り・ロボット初期姿勢 3 通り）。
**同じ `001500` をこれで測ると「効いた証拠なし」だった**——合計点 0.3674 → 0.3351、
タスクを対にすると成功が 9 対 20（符号検定 p = 0.061）。**採点側とは逆である。**

**理由は分かっている。手元の合計点はほぼ成功率の写しで、
Track1 で動いた「衝突となめらかさ」を見ていない**
（[../../knowledge/18_local_eval_missed_the_gain.md](../../knowledge/18_local_eval_missed_the_gain.md)）。

**帰結。この学習の良し悪しを判定できる物差しは、いまは 1 日 1 トラック 1 回の提出だけである。**
**だから重みは「1 日 1 つ出せる形」で刻んで残してほしい**（下の「やること」5 番）。

### すでに外したこと（同じ道を歩かないために）

| 外したもの | 何が起きたか |
|---|---|
| **行動側だけの学習** | 6,000 歩でも 24,000 歩でも loss は −1.0〜−3.3%。**画像側の重みは 0.000000 動かない。**手元の評価は落ちるタスクの中身まで一致した。**打ち止め** |
| 画像側を凍結したままの画像拡張 | 拡張ありが 0.625・なしが 0.750 で**悪化** |
| 推論の摘み（`infer`・`EMA`・`blend`・倍率） | 採点結果 10 本で動いたのは倍率 1.15 の −63%／−77%（**壊した**）だけ |
| 量子化（float8 ほか 5 候補） | 速さも精度も動かず。−53% は `torch.compile` の効果だった |
| 幾何の接ぎ木（VGGT） | 12,000 歩で寄与 26〜28% まで出たが、**bf16 の刻み幅で 2 層が学習できていない**（別セッションが継続中） |

**`compile_model` は必ず false のままにすること。**true だとチェックポイントに焼き付き、
**評価サーバの起動に 1,177.9 秒かかって落ちる。**

`001500` を足しても **0.13 エポック**である。**先頭集団との差はここだと読んでいる。**

## 何をしてほしいか

**`001500` から続けてフルパラメータ学習を回し、途中の重みを 1,000 歩ごとに
HF へ上げてほしい。歩数は受け側が決めてよい。**

成果物は **(1) HF に上がった `pretrained_model` の一覧**、**(2) 学習ログ**、
**(3) 下の「報告の書き方」の表**、**(4) 歩数をそう決めた理由 1〜2 行**である。

## なぜ要るか

**「フルパラメータ学習をどこまで伸ばすか」を決めるための材料になる。**
残り 19 日で、提出できるのは 1 日 1 トラック 1 回。**重みが 1,000 歩刻みで並んでいれば、
毎日 1 つずつ出して採点側で傾きが読める。**逆に 1 つだけ長く回すと、
上がったか下がったかは分かっても**どこで飽きたかが分からない。**

## 前提となる事実

### 決めてほしいこと 3 つと、こちらの見立て

| 決めること | こちらの見立て | 何を見て決めるか |
|---|---|---|
| **歩数** | **6,000 歩**（17 時間・$31〜37）。1,000 歩ごとに 6 個残る | 費用と、1 日 1 つ出す枠（19 日）との釣り合い。**9,000 歩（25.8 時間・$46〜56）でもよい** |
| **保存の間隔** | **1,000 歩ごと**。ただし Volume 150 GB に対しチェックポイントは 25 GB なので、**上げたら消す** | 上げ切るまでに次が出ると溢れる |
| **カメラ拡張を残すか** | **残す。**効いた実験の一部なので、**同時に 2 つ変えない** | 変えたいなら別の走りにする |

**学習率は `5e-6` を明示すること。**省くと頂点 2.5e-5 に戻り、
`rp3000` が 2.5e-6 で終わっているぶんの **10 倍**から再スタートする。

### `train_pi05.py` は転送が要る

**Pod のイメージ `:v2` に焼き込まれているのは 08-13 の版で、
`--camera-viewpoint-augment` が入っていない**（入ったのは 08-24 の `6ee31db`）。
**`/workspace` に残っている 8/17 の写しにも無い。**

```bash
# lab マシンから（116 KB・10 秒）
cd /home/ubuntu/lab/PARC2026_pre/solution/train && \
tar czf - --exclude='__pycache__' experiments train.py train_pi05.py | \
ssh -p <port> -i ~/.ssh/id_ed25519 root@<IP> 'tar xzf - -C /opt/pi05 --no-same-owner'
```

**`--no-same-owner` が要る**（`/workspace` は MFS で所有者の復元に失敗する）。
**`experiments/` も一緒に送ること**——現在の `train_pi05.py` は
`from experiments import geometry, quantization` を実行する。

### Pod の作り方で 2 回踏んでいる

| 踏んだこと | 対処 |
|---|---|
| **イメージ `:v1` には SSH が入っておらず、起動コマンドが空だと延々と再起動する** | イメージは **`sirukufarios/parc2026-train-pi05:v2`**、Container Start Command に **`bash /opt/pi05/runpod_ssh_start.sh`** |
| **Stop すると GPU を取られる** | 止めるときは終わらせる。**途中で Stop して再開する運用はしない** |
| `hf auth login` を忘れると非公開リポジトリが `not found` に見える | 先に `hf auth login`（`HF_HOME=/workspace/hf_home` は Volume 上なので一度で残る） |
| **Network Volume では `df` が答えない**（クラスタ全体の数字が出る） | 使用量は `du -sh /workspace/*`、枠は RunPod の Storage 画面 |
| `hf upload <repo> <file> .` は落ちる | 単一ファイルは `path_in_repo` にファイル名が要る |

詳しくは [../../knowledge/13_runpod_operations.md](../../knowledge/13_runpod_operations.md)。

## やること

1. **Pod を作る**（ユーザが RunPod の画面で。API キーはこちらに無い）。
   イメージ `sirukufarios/parc2026-train-pi05:v2`、
   Container Start Command `bash /opt/pi05/runpod_ssh_start.sh`、Volume 150 GB。

2. **`experiments/` と現在の `train_pi05.py` を転送し、確かめる。**

   ```bash
   python /opt/pi05/train_pi05.py --help | grep -c camera-viewpoint-augment   # 1 以上
   ```

   **0 のままならそこで止めて報告すること。**古い版で回してはいけない。

3. **初期重みを取る。`001500` である**（`rp3000` ではない）。

   ```bash
   hf auth login
   hf download siruku6/pi05_trial1500 --include '001500/*' --local-dir /workspace/init
   ls /workspace/init/001500/config.json /workspace/init/001500/model.safetensors
   ```

   **`--init-from` に渡すディレクトリの直下にこの 2 つが要る。**

4. **学習を始める。`tmux` の中で。**歩数は 1 番で決めたものを入れる。

   ```bash
   tmux new -s train
   cd /workspace
   python /opt/pi05/train_pi05.py --run-name pi05_long \
       --init-from /workspace/init/001500 \
       --camera-viewpoint-augment \
       --steps <決めた歩数> --batch-size 64 --num-workers 16 \
       --learning-rate 5e-6 --save-freq 1000 \
       --freeze-vision-encoder false --train-expert-only false
   ```

5. **始まって 2 分で `num_learnable_params` を確かめる。**

   | 値 | 意味 |
   |---|---|
   | **4143404816** | **正しい。全部を学習している** |
   | 693422112 | 行動側だけ。**2 つの `false` が効いていない。その場で止めること** |

6. **重みが出るたびに HF へ上げ、上げ終わったチェックポイントは消す。**
   **送り先を歩数ごとに分けること**（`.` にすると上書きし合う）。

   ```bash
   hf upload siruku6/pi05_long \
     /workspace/out/pi05_long/checkpoints/001000/pretrained_model 001000 --private
   ```

   **`vlm/`（17 MB のトークナイザ）を各歩数のディレクトリに入れておくこと。**
   学習のチェックポイントには付かず、**無いと評価も zip の組み立ても落ちる。**
   `001500` から `cp -r` する（`ln -s` では駄目）。

7. **ログを先に外へ出す。**45 KB のログが、後から「どこで平らになったか」を答える
   唯一の材料になる。`hf upload siruku6/pi05_long <ログ> pi05_long.log --private`。

8. **終わったら Pod を止める**（動かしている間ずっと課金される）。

## 報告

**回していない。回すのはユーザである。**この依頼に対して出したものは
**手順書 1 本**である——[../../howto/06_runpod_pi05.md](../../howto/06_runpod_pi05.md)
の **14 節「6,000 歩の長い学習を、上から順に打って終わらせる」**（14.1〜14.7）。
**確認コマンドと期待される出力の対、踏みそうな穴 11 個ごとの対処、
見張りの時刻表、終わり方まで、判断を挟まずに打てる形にしてある。**

### 1. 決めた 3 つ

| 決めたこと | 値 | 理由 |
|---|---|---|
| **歩数** | **6,000**（見立てどおり） | 10.24 秒/歩（[004 の報告](004_runpod_short_full_training.md)「2. 速さと費用」）で **17 時間 04 分**。**1 回の走りで終わるので Stop を挟まずに済む**（Stop は GPU を手放す操作である）。見た量は 0.13 → **0.30 エポック**（(3,000＋1,500＋6,000)×64 ÷ 2,238,036） |
| **保存の間隔** | **1,500 歩ごと（4 個）**——**見立ての 1,000 歩から変えた** | **上限は GPU 代ではなく HF の非公開の枠だった。**8/29 に測ると **84.34 GB／100 GB**、重み 1 個 **9.37 GB**。`parc2026-submission`（37.51 GB・使い捨て）を消しても入るのは **4 個**（46.83＋9.37×4＝84.3 GB で、次の提出 zip 1 本ぶんがちょうど残る）。**1,000 歩ごとの 6 個は 93.9 GB になり、zip を置く場所が無くなる。**加えて採点は 8 エピソードで 1 本 0.125 動くので、**1,500 歩差のほうが差が雑音を超えやすい** |
| **カメラ拡張** | **残す**（見立てどおり） | **`001500` はこの拡張つきで作った重みである。**外すと学習の途中で画像の性質が切り替わる。しかも 0.492／0.233 を出した設定から 2 つが同時に変わり、**上がっても下がっても、どちらのせいか読めなくなる** |

**測ったコマンドは 14.2 (b) にそのまま置いた**（`huggingface_hub` の
`model_info(..., expand=["usedStorage"])` を全リポジトリに掛けるもの）。
**これは開始前の確認の 1 つとして手順に組み込んである**——枠が 55 GB を超えていたら
`parc2026-submission` をリポジトリごと消す分岐（14.4 の D）に入る。

### 2. `libero_90` を足すか——**足さない**

**LeRobot 0.6.0 はデータセットを 1 つしか受け取らない。**

```
work/lerobot-src/src/lerobot/datasets/factory.py:116
    raise NotImplementedError("The MultiLeRobotDataset isn't supported for now.")
```

`make_dataset` は `cfg.dataset.repo_id` が文字列のときだけ動き、**リストを渡すと
この行で止まる**（`raise` は `MultiLeRobotDataset(...)` を組み立てる行の手前にある）。
`train_pi05.py` の側も `_DATASET_REPO = "lerobot/libero_plus"` を焼き込んでいて、
`_build_command` が `--dataset.repo_id=` を 1 つだけ出す。**引数で 2 つ目を足す口は無い。**

**足せるかどうかと、足すならどれだけの手間かは 14.7 に 1 節書いた。**
いちばん安い道は配布物の `libero_combined_20hz` へ `--dataset-root` で乗り換えることで、
**`train_pi05.py` を 1 行も直さずに済む。ただし中身をまだ数えていない**
（113 タスク・3,080,714 コマなら `libero_90` 入り）。

**今回足さない理由は手間だけではない。**

1. **同時に 2 つ変わると読めない。**歩数とデータを両方変えると、点が動いても
   どちらのせいか分からない。**0.492／0.233 と比べられる形を残すことがこの学習の目的である。**
2. **Track3 は全参加者 0.000 である。**足す価値がまだ誰の点でも確かめられていない。
3. **Track1 と Track2 は 40 タスクで採点される。**73 タスクを足すと、その 40 タスクに
   割り当たる量が半分以下に薄まる。**点が付いている 2 トラックを削って、
   まだ 0 点のトラックに賭ける形になる。**

### 4. 親に見直してほしい判断
