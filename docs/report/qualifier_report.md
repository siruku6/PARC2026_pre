# PARC2026 予選レポート

**提出モデル: `policy_server` 4.2.0 ／ ベースモデル: π₀.₅ (Pi05)**

## 1. 学習・推論時の工夫点および試行錯誤

### 1.1 ステップ数の上限が成否を分けるため、施策の採否をステップ数で判断した

採点ログから各エピソードが消費したステップ数（`/act` の呼び出し回数）を数え、総合スコアと
突き合わせた。**ステップ数の減少とスコアの上昇は強く結びついていた。**評価タスク・初期状態・
乱数シードは提出間で固定のため、下表の各行は**1 つの要素だけを変えた対照**である。

| 変えた要素 | 合計ステップ数 | 総合スコア |
|---|---|---|
| Action chunk 長 10 → **16** | 1,428 → **1,142（−20%）** | 0.177 → **0.264（+49%）** |
| chunk 境界の平滑化を追加 | 1,142 → **1,471（+29%）** | 0.264 → **0.169（−36%）** |
| 指示文の正規化を追加（**重みは不変**） | 1,922 → **1,617（−16%）** | 0.166 → **0.181（+9%）** |
| **重みを全パラメータ学習後のものへ** | 1,142 → **991（−13%）** | **0.264 → 0.485（+84%）** |

一方、**自己評価で動作の滑らかさを改善しても、スコアには結びつかなかった。**chunk 境界の
平滑化は自己評価で平均ジャークを 10% 下げ、成功タスクも 25→28 件に増やしたが、本番の総合
スコアは 0.264 → 0.169 と下がった。エピソードは 300 ステップで打ち切られるため、
**この変更は 8 エピソードのうち 2 本を打ち切りへ追い込んでいた。**以降は滑らかさの改善を
捨て、ステップ数の短縮に絞った。同じ機構をより厳密に実装した Real-Time Chunking も、
自己評価でステップ数が 39.5% 増えたため提出していない。

### 1.2 モデルの推論能力に合わせて Action chunk 長を調整した

**推論能力の低いモデルほど遠い未来の行動列を当てにくい**と考え、chunk 長は
モデルごとに測り直す方針を取った。短ければ観測を頻繁に取り込めるが、境界ごとに
別のモードを引いて動作が不連続になる。

| モデル | 採用した chunk 長 | 根拠 |
|---|---|---|
| SmolVLA (0.4B) | **2〜5** | 50→10→5→2 で単調改善、1 では悪化（0.166→0.080） |
| **π₀.₅ (4.14B)** | **16** | 10→16 で 0.177→0.264。32 は自己評価で 36 件中 13 件が打ち切り |

**実際に最適値はモデルの能力とともに大きくなった。**前モデルの最適値 2 を
そのまま流用していれば、0.264 には届かなかった。

### 1.3 配布 notebook が凍結している視覚エンコーダまで学習した

配布された学習用 notebook は `freeze_vision_encoder=true`・`train_expert_only=true` で
行動側のみを更新する。**1 回目の学習**はこれに倣ったが、**18,000 ステップ以降 loss が
0.2375 → 0.2352 → 0.2360 と頭打ちになった。**残存誤差が凍結側にある可能性を考え、
**2 回目の学習**では視覚エンコーダを含む全パラメータを解いた。**loss は 0.2100 まで低下し
（−11%）、打ち切り時点でも下降が続いていた。**本番スコアは 0.264 → 0.485、合計ステップ数は
13% 減少した。

### 1.4 その他

- **指示文の正規化**: 学習データの指示文 40 種はすべて小文字で `pick up the …`（21 種）
  などの形だが、配布された評価用タスクが渡す文は `Pick the akita black bowl …` のように
  大文字始まりで語も異なる。**非公開タスクにも同じ書き換えが適用されていると推測し**、
  受け取った文を学習データ側の 40 種のうち最も近いものへ寄せた。**重みを変えずに
  0.166 → 0.181。**

| **提出チェックポイントのハッシュ値** ※ | **`0c5d542e0052863a7d2caba141c076003b82d3156cd355654e4ba72cc8edfe6d`**（`model_weights/model.safetensors`）<br>**学習で内容が変わるのはこのファイルのみ**である。同ディレクトリの正規化統計（pre/post processor）はデータセットから計算される値で、2 回の学習を通じてバイト単位で同一。参考までに提出 zip 全体は `5cf6b9836f46805ba10bdde93ead02913c65d050adfb20d6800a3788b4cdb9ee` |

## 3. 学習情報

**同じデータで 2 回学習した。**左列は予選ルール p14 の項目名である。

| 項目 | 1 回目の学習 | 2 回目の学習 |
|---|---|---|
| 使用した学習データ | Hugging Face **`lerobot/libero_plus`** revision **`f3f49f426d75030177b18778374005bc12ccd588`**（LIBERO-plus を LeRobot 形式へ変換したもの）。**独自に収集・生成したデータは使用していない** | 1 回目と同じ |
| データ件数，タスク数，エピソード数等 | **14,347 エピソード／2,238,036 フレーム／40 タスク**。panda、20 fps、前方・手首の 2 視点と関節状態 | 1 回目と同じ |
| 学習方法 | **視覚エンコーダと VLM を凍結し、行動側のみを更新** | **1 回目の結果を出発点に、凍結を解いて全パラメータを更新** |
| 学習ステップ数または epoch 数 | **24,000 ステップ**（384,000 フレーム＝0.172 epoch） | **3,000 ステップ**（192,000 フレーム＝0.086 epoch） |
| 学習対象となったパラメータ | **693,422,112**（全体の 16.7%） | **4,143,404,816**（全部） |
| Full fine-tuning，LoRA，adapter 等の区分 | **部分 fine-tuning**（重みを直接更新。**LoRA・adapter は不使用**） | **Full fine-tuning**（重みの更新方式は 1 回目と同じ） |
| 使用した主なハイパーパラメータ | batch size 16<br>AdamW（betas 0.9/0.95、weight decay 0.01、gradient clipping 1.0、eps 1e-8）<br>学習率 **2.5e-5 → 2.5e-6**（cosine decay、warmup 1,000 ステップ）<br>乱数シード 42 | batch size **64**<br>最適化は 1 回目と同じ<br>学習率 **5e-6 → 2.5e-6**（減衰の形は 1 回目と同じ）<br>乱数シード 42 |

**2 回合わせて 576,000 フレーム＝データ全体の 0.257 epoch のみを使用した。**
