### `n_action_steps` は n=2 が谷底だった（8/13 確定）

**同じ重み同士でしか比べられない**ので、weak3x で固定した 3 点だけを見る
（EMA 0.3・samples=1 で共通）。**素の重みの 50→10→5 とは別の系列である**——
前に「4 回連続で単調改善」と書いたのは 2 つの重みを混ぜた誤りだった。

| n | 本番 | 早く終わった回 |
|---|---|---|
| 5 | 0.144 | 4/8 |
| **2** | **0.166** | 4/8 |
| 1 | **0.080** | **3/8** |

**n=1 の悪化は講義資料が機構まで説明している**（`docs/第7回 講義資料part1.pdf` p.10）。

> **k が短すぎる（k=2）** ／ チャンク境界のたびに分布から**別のモードをサンプル
> しうる** → **mode-jumping・jerky（ガクガク）な動き**

n=1 は**毎歩がその境界**になる。逆に k が長すぎる（k=100）と open-loop 区間が
伸びて応答性が落ちる。**一般に使われるのは k=16〜32** で、我々が n=2 で最良なのは
**モデルが弱く、誤差の蓄積を頻繁に打ち切る必要があるから**と読める。

**含意が 2 つある。**
1. **n を触る余地はもう小さい**（2 が谷底。5 と 1 の両側で落ちる）。
2. **モデルが強くなれば最適な n は上がる**。だから**次に効くのは重みの改善**で、
   その先で n を 5→16 側へ戻す価値が出る。

## 2. スコアの式が 3 回分で一致した

8/10 に立てた式が、8/12 の新しい点でもそのまま合った。

```
スコア = （成功した本数 / 8）× 係数

  0.096   = (2/8) × 0.384    素・n=10
  0.1409  = (3/8) × 0.376    素・n=5 ＋ EMA
  0.09507 = (2/8) × 0.380    λ=0.25      ← 8/12 の新しい点
```

**係数は 3 回とも 0.376〜0.384 に収まる。** 偶然の一致とは考えにくい。
ここから 2 つ言える。

1. **成功本数が読める。** 素は 3 本、λ=0.25 は 2 本、学習のみは 0 本。
2. **λ=0.25 は滑らかさを 1 も落としていない**（係数 0.380 対 0.376）。
   **失ったのは成功 1 本だけである。**

なお 0.016 はどの本数でも係数が合わない（1 本なら 0.128）。**成功 0 本で、
わずかな端数が残っているだけ**と読むのが自然である。

## 3. 差は「8 本のうち 1 本」だった

採点ログの `POST /reset` がエピソードの開始、次の `/reset` までの `POST /act`
の回数がそのエピソードの歩数である。3 回分を並べるとこうなる（上限 300 歩）。

| 重み | ep1 | ep2 | ep3 | ep4 | ep5 | ep6 | ep7 | ep8 | 途中で終わった本数 |
|---|---|---|---|---|---|---|---|---|---|
| 素 0.1409 | 300 | 300 | 300 | 300 | 138 | 132 | 174 | 182 | **4** |
| λ=0.25 0.09507 | 300 | 300 | 300 | 300 | 143 | 177 | **300** | 168 | **3** |
| 学習のみ 0.016 | 300 | 300 | 300 | 300 | 234 | **300** | 139 | **300** | **2** |

**1〜4 本目は、3 種類の重みすべてで 300 歩に張り付いている。**
どの重みでも終われないタスクなので、**差がつくのは残り 4 本だけである。**

そして **0.1409 と 0.09507 の違いは、7 本目が 174 歩で終わったか 300 歩まで
走ったかの 1 本だけ**である。

> **だから 0.1409 と 0.09507 の優劣は判定できない。** 8 本のうち実質 4 本で
> 1 本の差なので、運の範囲に収まる。**明確に違うのは 0.016 だけである。**

途中で終わった本数（4 / 3 / 2）は成功本数（3 / 2 / 0）より 1 本ずつ多い。
**どの回も 1〜2 本は衝突で失格している。**

## 4. 手元の評価が本番と逆になる原因が分かった

8/11 の 84 件の評価はこうだった。

| | 手元 84 件 | 本番 |
|---|---|---|
| 素 | 0.476 | **0.1409（成功 3/8）** |
| 学習のみ | **0.500** | **0.016（成功 0/8）** |

**手元は「学習後のほうが良い」と言い、本番は「9 倍悪い」と言った。**
どちらの数字も正しく、**測っているものが違う。**

### 原因：学習に使ったタスクを検証にも使っている

- **学習側**: `solution/train/train.py` の `_select_episodes` は
  「**全 40 タスクから**」選ぶと docstring に書いてあり、**タスクを外す引数が
  1 つも無い。**
- **検証側**: 84 件は LIBERO-plus の `task_classification.json` から作る。
  これは**同じ 40 タスクの摂動版**である（`task_id` の `_table_1` や
  `_view_0_0_...` が摂動で、指示文は元のタスクのまま）。

**つまり検証タスクは学習済みである。** 手元の 0.500 は「覚えた度合い」を
測っていた。しかも `train.py` の 108 行目にはこう書いてある。

> **苦手タスクの割合を上げる。** 84 件の検証用データで切り分けたら…

**検証の結果が学習データの配分まで決めている。** 二重に混ざっている。

### もう 1 つ：素の重みは既に同じデータで学習し終えている

素の重みに同梱の `train_config.json` にこう書いてある。

| 項目 | 値 |
|---|---|
| `pretrained_path` | `lerobot/smolvla_base` |
| `steps` | **20,000** |
| `batch_size` | 32 |

**素の重みは、すでに LIBERO-plus で 20,000 歩学習し終えたものである。**
そこへ同じ LIBERO-plus で LoRA 20,000 歩を重ねた。**吸収済みのデータを
もう一度当てている**ので、得るものは小さく、重みがずれる損だけが残る。

**λ の 3 点（0 → 0.1409、0.25 → 0.09507、1.0 → 0.016）は、混ぜるほど
悪くなる形で、素を超える点が無い。**

### 申し送りは書いた

検証集合を作り直している別セッション向けに
[handoff_validation_set.md](handoff_validation_set.md) を置いた。要点は
**「件数を減らすのは正しいが、それだけでは直らない。タスク（指示文）単位で
学習と検証を分ける必要がある」**である。`libero_plus_id` で 84 件を外すだけでは
足りない（摂動版は元タスクの実演データを共有するため）。

他の 6 カテゴリを壊す経路が無い。

**ただし単語の重なりでは寄せられない** —— 言い換えは物の名前を避けているので、
`tomato sauce` と `red condiment ... garden fruits` に共通語がほとんど無い。
**意味で寄せる必要がある**（同梱の SmolVLM で文を埋め込む）。
Q&A No.31 が「**学習データの指示文集合への埋め込み最近傍を用いた入力正規化**」を
明示的に許可している。**最近傍の結果をタスク ID として分岐に使わない**こと。

**注意（資格）。** つまみだけの提出は不可（No.36）。**必ず weak3x（学習済み）に
載せる**こと。素に載せると資格で弾かれる。

### 手元の評価は直った（別セッション・8/13）

**既定が 36 件になった**（`compe/val/EVAL_TASKS.csv`）。
**weak3x が 1 度も引かなかった変種だけ**で作ってあるので、**weak3x 系の重みには
本物の代理になる。** 84 件は「壊れていないかの確認」用に降格。
所要も 2 時間 21 分 → **約 1 時間**。

> **ただし全件を使った回（lora20k・text40k）には除外にならない。**
> あの 36 件は weak3x の 4,609 本を基準に選んでいる。**基準を取り違えないこと。**
