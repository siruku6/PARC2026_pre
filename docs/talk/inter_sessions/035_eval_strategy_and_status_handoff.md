## 何をしてほしいか

1. **今すぐ：GPUで動いている評価の状況を引き継ぎ、判断する。**（下の「前提となる事実」参照）
2. **今日中：`pi05_l90clean_008000`（＋必要なら Adaptive Resampling をかけた版）を、
   Track1・Track2 フォームへ差し替えるかどうかを決め、締切までに実行する。**
3. **今後：評価方針の検討（次に何を測るか）と、複数セッションが同じ RTX6000 を使うときの
   衝突管理を、引き続き担当する。**

## なぜ要るか

- **締切が今日 23:59 である。**`pi05_l90clean_008000` は bowl5_full（＝現在の提出 15.0.0）を
  ローカル評価で上回っているが、**まだ1件も本選へ出していない。**出さなければ、より良い候補を
  手元に置いたまま締切を迎えることになる。
- **GPU（RTX6000・24GB）はこのマシンに1枚だけで、複数セッションが同時に使おうとしている。**
  今日すでに2回、セッション間で GPU の使い方がすれ違った（下記）。**方針を検討する側と、
  データ・学習を専門に担当する側を分けて、後者に評価の割り込み判断をさせないようにする**
  （発行元セッションの新しい専門領域に集中させるため）。

## やること

1. **腕Bを止めるか続けるかを決める。**止めるなら PID 2952991 系を確認して `kill`（**腕Aの結果は
   すでにディスクに書き終わっているので影響しない**）。続けるなら、ETA と GPU占有の見込みを
   `_lane_molmoact2_2arm.out` から読んで、他の評価が待つ時間を見積もる。
2. **`pi05_l90clean_008000` の Adaptive Resampling 評価を、`track1`/`track2` の引数を直した上で
   再開するか判断する**（GPUが空いてから。上記「前提となる事実」参照）。
3. **`pi05_l90clean_008000`（および Adaptive をかけた版があれば）を、締切までに
   Track1・Track2 フォームへ出すかどうかを決め、出す場合は実行する。**
   手順は `docs/howto/02_build_submission.md`。**出したら `reference/19` の
   「トラックごとの最終提出」表を更新すること。**
4. **今後、評価方針の検討（次に何を測るか）と、GPU・複数セッションの衝突管理を担当する。**
   発行元セッション（初期姿勢摂動の担当）から評価の依頼が来たら、この依頼の枠内で判断してよい。
