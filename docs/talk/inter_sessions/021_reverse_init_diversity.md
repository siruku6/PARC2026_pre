# 021 逆向きデータの初期配置を、配布 init の 50 行より広げる

> **状態: 依頼中** ／ 受け側: 未定 ／ 更新: 2026-09-07
>
> **やるかどうかも含めて未確定である。**まず「いま何通りあるのか」と
> 「増やす値打ちがあるのか」を測るところから、この依頼に含まれる。

## 1. いま何通りあるのか

逆向きエピソードの初期状態は、**配布 T3 の `.pruned_init` をそのまま使っている**。
これは 1 タスクにつき **50 行**入っている（[reference/28 の 5.5 節](../../reference/28_track3_contents.md)）。

**1 タスクで作れる本数は「50 行 × 順方向デモの本数」で頭打ちになる。**いまの
389 本はその通りの数である（本 3×50、缶 2×50、マグ 3×50 のうち 139）。

### 測ってある事実

| | 結果 |
|---|---|
| 物の置かれ方（50 行） | **全部違う。**xy も向きも散っている |
| 邪魔な物の置かれ方 | **全部違う** |
| **腕の初期姿勢** | **50 行すべて同一**（ばらつき 0.00 mm） |
| 物の倒れ方 | **立っている行しかない。**倒れた本は配布にも LIBERO-90 にも 1 行も無い（[reference/28 の 5.5 節](../../reference/28_track3_contents.md)） |

**いちばん露骨に欠けているのは腕の初期姿勢である。**全エピソードで腕が同じ所から
始まるので、**「どこから始めても掴みに行ける」は 1 度も教えていない。**

## 2. なぜ気にするか

**Track2 の実測で、ロボット初期姿勢は効くほうに分類されている**
（[002](002_robot_init_pose_coverage.md)）。Track3 は未知ドメインでも採点される
ので、同じ穴がそのまま出る。

**ただし「増やせば良くなる」は測っていない。**389 本で学習した結果もまだ無い。
**だからこの依頼は「増やす」より先に「増やす値打ちがあるか」を出すのが本題である。**

## 3. 増やし方の候補

**3 つある。手間も、効く先も違う。**どれを採るか（あるいは採らないか）を決めるのが
この依頼の成果物である。

### 3.1 腕の初期姿勢を振る —— **いちばん安い**

配布 init の腕の関節角に揺らぎを足すだけで、**50 行が実質 50×N 通りになる。**
物の配置は配布のまま使えるので、目標条件の妥当性も崩れない。

- 振り方の設計は [002](002_robot_init_pose_coverage.md) が既に持っている
  （**公式の 500 通りは 1 つの基準姿勢のまわりのゆらぎでしかない**という指摘も含む）
- 振った姿勢から掴む姿勢へ届くかは、`rollout_phased` の接近段が勝手に面倒を見る。
  **届かなかった回は逆向き goal が落ちるので、自動で弾かれる**
- **`MAX_APPROACH` を上げる必要が出る**（腕が遠い所から始まるため）

### 3.2 物の配置を bddl の `:regions` から引き直す

`.pruned_init` の 50 行を使う代わりに、**bddl の `:ranges` から自分で抽選する**。
仕組みは既にある。

| 要るもの | ある場所 |
|---|---|
| 物の姿勢だけ差し替えた初期状態を作る | `gripper_shift_sweep.with_object_qpos` |
| 別の env の同じ site の座標系へ姿勢を移す | `gripper_shift_sweep.rebase_qpos` |
| 領域の箱の中心と半サイズ | `gripper_shift_sweep.region_box` |

**注意: 同じ名前の領域でも、定義ファイルが違えば広さが違う。**順方向 libero_90 の
`study_table_yellow_book_left_init_region` は ±10 mm だが、配布 T3 の同名は
**±75 mm** である（`eval_in_t3` の docstring に実測がある）。**どちらの箱で
抽選するのかを間違えないこと。**

### 3.3 倒れた姿勢を作る —— **いちばん高いが、他に代わりが無い**

**倒れた物の初期状態は、配布にも LIBERO-90 にも存在しない。**隠しタスクで出たら
学習データに 1 本も無い状態で当たることになる。`--init-source t3-lying` が
その入口だが、**このルートは init 行を変えても結果が変わらない**（物の姿勢を
上書きするため）ので、**順方向デモ 1 本につき 1 通りしか作れない**
（[018 の 5 節](018_reverse_dataset_writeout_plan.md)）。ここを増やすには
倒し方そのものを抽選する必要がある。

## 4. 進め方の提案

**1 → 2 → 3 の順。1 で止めてよい結果が出る見込みもある。**

| # | やること | なぜその順か |
|---|---|---|
| 1 | **いまの 389 本で学習して点を出す** | **これが無いと、増やした効果を測る物差しが無い。**増やす作業より先に来る |
| 2 | **3.1（腕の初期姿勢）だけで増やして比べる** | いちばん安く、いちばん欠けている軸。物の配置は配布のまま使えるので副作用が少ない |
| 3 | 3.2 / 3.3 の要否を、2 の結果を見て決める | どちらも「作った初期状態が妥当か」を自分で保証する必要があり、値段が上がる |

**増やす前に必ず出しておく数字。**

- いまの 389 本の内訳（タスク × 順方向デモ × init 行）
- 1 本あたりの生成時間（増やしたとき何時間かかるかがこれで決まる）

## 5. 落とし穴

| 何 | どうなるか |
|---|---|
| 初期状態を自分で作ると、**目標条件が成り立たない配置**を作り得る | 逆向き goal で弾かれるが、**歩留まりが落ちる**。抽選の前に箱の中かを確かめる |
| 腕を遠くから始めると接近が足りない | `MAX_APPROACH` の既定 60 は本タスク（約 200 mm）の値。缶・マグは既に 120 が要る |
| 物を増やしても**擦る・落とす**は別問題 | 置き方の設定（[reference/31](../../reference/31_reverse_place_without_contact.md)）は初期配置と独立に効く。増やすときも `LIFT` / `RELEASE` / `LEVEL` を落とさないこと |
