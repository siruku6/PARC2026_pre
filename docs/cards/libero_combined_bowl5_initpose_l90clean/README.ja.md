# libero_combined_bowl5_initpose_l90clean

*English: [README.md](README.md)*

**LIBERO** の操作課題のための、LeRobot 形式の実演データである。
配布の LIBERO / LIBERO-plus から組み直してあり、狙いは**誤ったことを教えていた 3 つ**を取り除くことである——
**対象外の物体にぶつかる手本**、**「開く」に逆の正解が付く指の符号**、
**評価を覆えないほど狭いロボット初期姿勢の分布**。

| | |
|---|---|
| 本数 | **21,642** |
| コマ数 | **3,431,137** |
| 課題数 | **111** |
| 大きさ | 27.8 GB |
| 形式 | LeRobot v2.1・20 Hz |
| カメラ | 場面（`observation.images.image`）と手首（`observation.images.wrist_image`）・256×256 |
| 状態 / 行動 | 8 次元の状態・7 次元の差分エンドエフェクタ姿勢 |

ロボット操作のコンペ **PARC2026** のために作った。

## どう組んだか

**このデータは連鎖の最後である。**各段で何を変えたかを並べるので、
合わない変更があれば手前の版を選べばよい。

```
LIBERO-plus（配布）
  └─ libero_plus_bowl5            丼課題を撮り直す                  14,085 本
      └─ libero_plus_bowl5_initpose   接触を外し、初期姿勢を振る      16,820 本
          └─ libero_combined_bowl5_initpose   + libero_90 と標準スイート  21,642 本
              └─ libero_combined_bowl5_initpose_l90clean  ← このデータ   21,642 本
```

### 1. 丼課題を撮り直す（`libero_plus_bowl5`）

配布データの中で衝突率がいちばん高かったのが「丼」5 課題だった。**1,880 本を全部外し**、
台本で動かす方策の手本に入れ替えた。**掴む半径を縁の壁の中心に合わせ、降りる勢いを絞ってある。**
入れ替えた手本は、収録前に摂動込みで 130/150 の成功率まで確かめた。

### 2. 接触を外し、初期姿勢を振る（`libero_plus_bowl5_initpose`）

- **1,532 本を外した**——対象外の物体に接触している本と、300 コマを超える本
  （300 コマは評価の打ち切り上限である）。
- **3,972 本を新しく収録して埋め戻した。ロボットの初期姿勢を振り**、
  そのうえに外観（照明・机と背景・カメラ）を重ねてある。
  **外観を変えても物理が 1 ビットも変わらないことを確かめたうえで重ねている**ので、
  物理側の分布は薄まらない。
- **さらに 303 本**を、300 コマ超で外した本について短く撮り直して足した。
- 全体に掛けた歯止め——1 つの元デモから作る変種は 3 本まで、ゴールの 10 歩後で切る
  （配布データと同じ）、指示文は配布データの書き方に寄せる。

### 3. 標準スイートを足す（`libero_combined_bowl5_initpose`）

配布 `libero_combined_20hz` の先頭 5,186 本を後ろに繋いだ。内訳は標準スイート
（`libero_10`・`libero_spatial`・`libero_object`。1,265 本）と **`libero_90`**（3,921 本）で、
合わせて 111 課題になる。

**指の符号を直したのはここである。**これらの本の先頭の指の値は `{0, 1}` で、
他のデータは `±1` を使っている。**直さないと「開く」に逆の正解が付く。**

外す規則は出どころで違う。標準スイートは上と同じ規則（丼 5 課題 218・300 コマ超 65・接触 71）、
**`libero_90` は 300 コマ超の 10 本だけ**——接触の判定に要る本家の hdf5 が手元に無かったためである。

### 4. libero_90 を掃除する（このデータ）

**汚れと判定した `libero_90` の 250 本を、同じ課題・同じ本数の綺麗な手本に置き換えた。**
課題ごとの本数は変わらず、コマ数だけ減っている（親より −5,803）。

**置き換えた 250 本はデータの末尾に付いている**ので、**本の番号で親の版と対応は取れない。**

## 分かっている弱点

- **`libero_90` の部分は接触の掃除をしていない。**1・2 段で掃除したのは LIBERO-plus の
  40 課題で、`libero_90` は 300 コマ超を外しただけである。
  **したがって課題によって手本の質が揃っていない。**
- **データを足すことが、確実に効くわけではなかった。**親（`libero_combined_bowl5_initpose`）で
  学習した模型は、より小さい `libero_plus_bowl5` で学習した模型に、
  手元の評価ではっきり**負けた**（0.3515 対 0.4055）。
  **40 課題から 111 課題へ広げたことが、その指標では裏目に出ている。**
  「課題を増やす」は試すべき仮説であって、改善ではない。
- **このデータでの続きの学習が、良い模型を壊した。**コンペで 0.498 を出したチェックポイントから
  ここで 8,000 歩続けたところ、`libero_90` の課題では高くなり（0.422 対 0.156）、
  **狙っている課題の分布では親と見分けが付かなくなった。**
  そのコンペでの点は綺麗な測定ではない——その提出はトークナイザを間違えて組んでいた——が、
  **何と引き換えに何を得たかは見えている。**
- **外観の変化は、コマごとに振ったものではなく重ねたものである。**収録の時点で掛けるので、
  1 本の中では終始 1 つの外観になる。
