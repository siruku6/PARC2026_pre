# 16. SmolVLAの「weak3x」の選び方を、π0.5にも使うべきか

**結論。weak3xは2つの別の工夫が合わさったものであり、π0.5への移りやすさが
まったく違う。**

| weak3xの中身 | π0.5に移せるか |
|---|---|
| **300歩を超える手本を落とす**(`--max-demo-steps 300`) | **移せる。** 理由が採点規則(300歩打ち切り)なのでモデルに依存しない。ただし**コードを直さないと落ちる**(4節)ことと、**mokaのタスクが丸ごと消える**(3節)ことに注意 |
| **苦手3タスクの割合を3倍にし、得意タスクを27%に間引く**(`--emphasize-tasks`) | **勧めない。** 出発点の重みの性質がSmolVLAと逆で、間引く73%こそπ0.5がまだ見ていないものである(2節) |

> |---|---|

## 1. 引数は既にある。コードを足す必要はない

`train_pi05.py`は`train.py`から選び方をそのまま輸入しており
(114〜121行の`from train import ... _select_emphasized_episodes`)、
`--emphasize-tasks` `--emphasis-multiplier` `--max-demo-steps`
`--holdout-tasks` `--dataset-root`をすでに受け取る(149〜156行)。

**実際に同じ選び方を手元で走らせ、SmolVLAのときと同じ4,609本になることを
確認した**(データセットのメタデータから再現。`train.py`の
`_select_emphasized_episodes`と同じ計算をやり直した)。つまり
**やること自体は、コマンドに引数を足すだけで足りる。**

## 2. それでも勧めない理由——出発点の重みの性質が逆である

**ここがいちばん大事な違いである。**

| | SmolVLA | π0.5 |
|---|---|---|
| 出発点の重み | `lerobot/smolvla_libero_plus` | `lerobot/pi05_libero_base` |
| その重みが学習に使ったデータ | **`pepijn223/libero_plus_lerobot`(＝今回のデータそのもの)** | **`lerobot/libero`(素のLIBERO。今回のデータではない)** |
| 今回の追加学習の役割 | すでに馴染んでいる分布の中で、**苦手を狙って強める** | **libero_plusの見た目のばらつきに、初めて馴染ませる** |

**SmolVLAでは、間引いた73%の見た目はすでに重みの中に入っていた。** だから
得意タスクを27%に減らしても失うものが小さく、苦手タスクの割合を上げる分だけが
効いた。**weak3xは「すでに馴染んだモデルへの重み付け直し」である。**

**π0.5の出発点は素のLIBEROでしか学習されていない**(モデルカードのコード例が
`LeRobotDataset("lerobot/libero")`と書いている)。libero_plusが足している
見た目・照明・カメラ・言い換えのばらつきを**一度も見ていない**。この1回の学習が
やるべきことは、その初回の馴染ませである。**得意タスクを27%に間引く操作は、
その馴染ませに使う材料を7割捨てることに当たる。**

同じ操作が、一方では「失うものが小さい重み付け」、他方では「材料を捨てる」に
なる。**weak3xの費用と効果は、2つのモデルの間で逆さになっている。**

### 「引ける回数が足りない」という理屈は、たしかに当てはまる

weak3xの元々の根拠は「引ける回数が足りないのであって、データは足りていない」
だった(`train.py`の`_select_emphasized_episodes`のdocstring)。
π0.5では引く回数がさらに少ないので、**この理屈自体はより強く当てはまる。**

**メタデータから計算した実数**(π0.5の引く回数 = 24,000歩 × バッチ16 = 384,000回)。

| データの選び方 | 本数 | フレーム | **1コマを見る回数** |
|---|---|---|---|
| 全部(いまの設定) | 14,347 | 2,238,036 | **0.17** |
| 300歩超だけ落とす | 13,946 | 2,096,321 | 0.18 |
| 苦手1.5倍 | 9,277 | 1,398,342 | 0.27 |
| 苦手2倍 | 6,939 | 1,046,644 | 0.37 |
| **苦手3倍(weak3xと同じ)** | **4,609** | **699,411** | **0.55** |
| (参考)SmolVLAのweak3x(640,000回引いた) | 4,609 | 699,411 | 0.92 |
| (参考)本番0.016に落ちたlora20k | 200本 | — | 5.1 |

**0.55は、壊れた5.1からは遠く、安全な側である。** だから「危ないからやめる」
という話ではない。**やめる理由は2節の前半、材料を捨てることの方である。**

**逆向きの読み方も成り立つ。** 0.17回というのは、データの17%しか実質使えて
いないとも読める。ただし**広い集合から17%を引くのと、狭い集合から55%を引くのとでは、
見るものの多様さが違う。** 初めて馴染ませる段では多様さの側が効きやすい、
という判断で「全部」を勧めている。**これは測っていない判断である**(5節)。

### 苦手3タスクの選び直しも要る

強調している3タスクは**SmolVLAの評価で落ちたもの**である。

    put the bowl on top of the cabinet                                    (445本)
    put both the alphabet soup and the cream cheese box in the basket     (370本)
    pick up the black bowl next to the ramekin and place it on the plate  (380本)

**π0.5はまだ一度も評価していないので、何が苦手か分かっていない。**
別のモデルの苦手を強調するのは当て推量になる。

## 3. `--max-demo-steps 300`は「mokaのタスクを丸ごと消す」

300歩超を落とす操作は**モデルに依存しない**(採点が300歩で打ち切るので、
300歩を超える手本は再現できず、遅い動きを教えるだけになる)。落ちるのは
14,347本のうち**401本(2.8%)**だけで、影響は小さい。

**ただし1タスクが丸ごと消える。**

    put both moka pots on the stove

**手作業の手本を作っている相手そのものである**(`work/train/scripted_mix`、
`work/gpu_eval/*_weak3x_moka_*`)。手作業の分を混ぜる計画
([docs/howto/07](../howto/07_train_pi05_local.md)の次にやること2番)と
組み合わせると、**実データのmokaが消えて手作業の分だけが残る**という形になる。
それを狙っているなら問題ないが、**気づかずにそうなるのは避けたい。**

## 4. `--max-demo-steps`だけを渡すと落ちる(未修正のバグ)

**`--emphasize-tasks`を付けずに`--max-demo-steps 300`だけを渡すと
`ZeroDivisionError`で止まる。** `train.py`の`_select_emphasized_episodes`が

```python
share_now = weak_frames / (weak_frames + strong_frames)   # 強調が空なら 0.0
share_target = min(multiplier * share_now, 0.9)           # → 0.0
keep_ratio = weak_frames * (1.0 - share_target) / (share_target * strong_frames)
#            0 * 1.0 / (0.0 * strong_frames)  →  0.0 / 0.0
```

を計算するためである(2026-08-13に同じ計算を手元で再現して確認)。
`train.py`側にも同じバグがあり、**pi05固有ではない**(SmolVLAでも
`--max-demo-steps`を単独で使ったことが無かった)。

直すなら、`keep_ratio`の計算の前に「強調が空なら間引かない」を1つ足す
2〜3行で済む。

```python
if not wanted:
    keep_ratio = 1.0
else:
    keep_ratio = min(weak_frames * (1.0 - share_target) / (share_target * strong_frames), 1.0)
```

## 付記: 「資格」の理由はπ0.5には要らない

SmolVLAでweak3xを最終提出に載せた理由は、**スコアではなく資格**だった
(素の重み0.1409は学習していないので提出できない)。運営Q&A No.36の回答は

> 独自の学習を行うことが必須である点(形式変換・名称変更・推論パラメータ変更の
> みの提出は不可)は従来どおりですので、ご留意ください。

**π0.5はどのデータで回しても独自の学習なので、この要件はデータの選び方と無関係に
満たされる。** weak3xを使う理由のうち、いちばん強かった1つがπ0.5では消える。

なお**weak3x自体のスコアの効果は、実は測れていない**。0.1409(素)→0.144の差は
本番8本のうち0.6本ぶんで、「学習が素を超えた」とは言えないと記録されている
(`docs/strategy/05_実測結果.md`の訂正)。
