## 背景（先に読んでほしい）

**このコンペで何をしているか。** PARC2026 の本選 1 である。ロボット（Franka Emika Panda）に
自然言語の指示を与え、LIBERO-plus のシミュレータの中で物を掴んで運ばせる。
こちらの方策は **π0.5**（PaliGemma 2B ＋ 視覚側 SigLIP ＋ 行動側 300M、合計 41 億パラメータ）。

**いまの立ち位置。**

| トラック | こちらの点 | リーダーボードの最高 |
|---|---|---|
| Track1 | **0.370** | **0.65** |
| Track2 | **0.207** | **0.53** |
| Track3 | 0.000 | 0.000（全参加者） |

**多くの参加者が 0.4 を超えている。こちらは先頭集団の下にいる。**

**なぜ学習なのか。** こちらが**全パラメータを学習したのは 3,000 ステップだけ**である
（8/17・RunPod A100 80GB・batch 64・8 時間 33 分・`work/artifacts/pi05_rp3000`）。
学習データ全体の **0.085 エポック**にすぎない。それ以降にやった 6,000 歩と 24,000 歩は
**行動側だけ**で、画像側は 1 ビットも動いていない（重みを直接比べて 0.000000 と確認済み）。
**loss は 24,000 歩でも -1.0〜-3.3% しか動かず、手元の評価も落ちるタスクの中身まで一致した。**

**つまり「素直な学習がまだ足りていない」が、いちばん素直な読みである。**
先頭集団は、予選で学習した重みをさらに学習しているか、本選で新しく学習していると見ている。

**ただし、学習が効くという確証はまだ無い。** 直近で 1 つ悪い前例がある——
**画像側を凍結したままカメラ拡張を入れた 6,000 歩の学習は、素の重みより悪くなった**
（衝突率が 0.250 → 0.375 に増えた）。**画像側を開けば直る、というのはこちらの読みであって、
測った事実ではない。**

## この依頼の狙い

**「9,000 ステップを回す段取りを作る」から「短く試してから決める」へ組み替えた。**
理由は 2 つある。

| 理由 | 中身 |
|---|---|
| **時間の上限に入らない** | 9,000 ステップは **25.8 時間**（6.2 samples/s・batch 64 での計算）。**Blackwell は 1 セッション 12 時間で自動停止する。**2 倍速くても 13 時間で、まだ入らない |
| **効くかどうかがまだ分からない** | 上の「悪い前例」がある。**26 時間と 60 時間のうちの半分近くを、効くか分からないものに賭けることになる** |

**だから順序を逆にする。まず 1 セッションに収まる短い学習を回し、
効く方向に動いていることを確かめてから、長い学習に踏み切る。**

## 何をしてほしいか

**Blackwell の 1 セッション（12 時間）に収まる「お試しの学習」を設計し、
Notebook に貼るセルの列と、その結果で長い学習に進むかを決める基準を作ってほしい。**

成果物は **(1) 貼るだけのセルの列**、**(2) 60 時間の使い道の表**、
**(3) 長い学習に進んでよいかの判定条件**である。

## 前提となる事実

**時間の制約**（`docs/howto/14_blackwell_first_session.md`）。

| 制約 | 値 |
|---|---|
| 本選 1 の期間全体 | **60 時間**。起動してから自分で止めるまで減り続ける |
| **1 セッション** | **起動から 12 時間で自動停止** |
| 何も実行していないとき | 1 時間で自動停止（学習中は関係ない） |
| 止め方 | `File > Hub Control Panel > Stop Server`。**押した瞬間に消費が止まる** |

**自分の Docker イメージは持ち込めない。** 2026-08-26 の資料 v1.1 でサポート外になった。
**Notebook の Python 環境へ直に pip で入れる。**

**学習のコマンド**（`docs/plan/15_runpod_fullparam_with_augment.md`）。

```bash
python train_pi05.py --run-name pi05_trial \
    --init-from <出発点の重み> \
    --camera-viewpoint-augment \
    --steps <お試しの歩数> --batch-size 64 --num-workers 16 \
    --learning-rate 5e-6 --save-freq <途中で残す間隔> \
    --freeze-vision-encoder false --train-expert-only false
```

**起動直後に必ず確かめる 1 つ。** ログの `num_learnable_params` が **4143404816** であること。
**693422112 になっていたら行動側しか学習していない**ので、その場で止める。

**`compile_model` は `false` のままにすること。** `true` だとチェックポイントに焼き付き、
評価サーバの起動が 1,177.9 秒かかって落ちる。

**出発点の重み。** `work/artifacts/pi05_rp3000`。手元にあり、HF の私有リポジトリにもある。

**コードの持ち込み方。** HF の私有リポジトリ経由が速い（前例は 46 KB の tar.gz）。
**scp は 1.7 MB/s しか出ない。**

**評価のしかた。** 学習した重みは**会社の RTX6000 で**評価する（Blackwell では評価しない
——時間がもったいない）。集合は `compe/val/TRACK2_VAL72.csv`（72 行 × 3 エピソード = 216 本、
**約 1 時間**）。点は `solution/tools/eval/score_composite.py` で出す。
**比べる相手は `pi05_rp3000` の 0.3674 である。**

**ばらつきの目安。** 216 本での成功率の標準誤差はおよそ 0.031 なので、
**合計点で 0.04 未満の差は「動いた」と言えない。**

## やること

1. **お試しの歩数を決める。**
   - **1 セッション（12 時間）に、環境作りと重みの往復も含めて収まること。**
   - **途中の重みが 3 つ以上残ること**——1 点だけ見ても、上がっているのか下がっているのかが
     分からない。**傾きを見たい。**
   - 速さは Blackwell に入るまで分からないので、**「測ってから歩数を決める」形にする。**
     最初の 200 ステップで samples/s を測り、そこから歩数を逆算するセルにすること。
     **参考値は RunPod A100 80GB で 6.2 samples/s（batch 64・全パラメータ）。**

2. **貼るだけのセルの列にする。** 下見 → pip → コード取得 → 重み取得 → **速さの測定** →
   歩数の決定 → 学習 → 途中の重みを外へ退避、の順。**1 セル 1 目的**にして、
   途中から流せるようにする。`notebook-runbook` スキルに沿うこと。

3. **重みを外へ出す道を作る。** セッションが消えると中身も消える。
   **途中の重みが出るたびに HF の私有リポジトリへ上げる**形にしておく。
   **1 個 25 GB あるので、上げる時間も 60 時間から引かれることを見積もりに入れる。**

4. **60 時間の使い道を表にする。** 下見・環境作り・重みの往復に何時間持っていかれるかを、
   学習そのものの時間と**分けて**書く。**お試しに何時間、残りが何時間かを出す。**

5. **長い学習に進んでよいかの判定条件を書く。**
   RTX6000 で 72 行を回して合計点を出したとき、**どうなっていたら進み、
   どうなっていたら止めるか**を、数値で書くこと。**傾きで判定する形にする。**
   `pi05_rp3000` の 0.3674 と、ばらつき 0.04 を使ってよい。

6. **長い学習に進む場合にだけ要る「再開の道」は、5 の判定条件と一緒に書くだけでよい。**
   **いま作り込まなくてよい。**必要になったら別の依頼にする。
   ただし **1 つだけ確かめてほしい**——`/opt/lerobot` のコードで、
   **チェックポイントから再開したときに学習率のスケジュールが続きになるのか、
   最初からやり直しになるのか。**やり直しになるなら、長い学習の設計そのものが変わる。

## できあがりの条件

- セルを上から流すだけで、お試しの学習が始まる
- **速さを測って歩数を決める形になっている**（歩数が決め打ちになっていない）
- 途中の重みが 3 つ以上、Blackwell の外に残る
- **「進む・止める」の判定条件が数値で書いてある**
- 60 時間の使い道が表になっている
- 学習率スケジュールが再開で続くかどうかの答えが 1 行ある

## 報告の書き方

1. **お試しの設計**——何ステップ、何時間、途中の重みは何個。**5 行以内。**
2. **60 時間の割り振りの表。**
3. **判定条件**——数値で。
4. **学習率スケジュールの再開について**、1 行。
5. **危ないところ 3 つ**——失敗したらどう気づくかを添えて。
