## 1. 同じ版番号が別の中身を指した

**版番号は、提出物の zip を 1 つに決めるための名前である。それが 2 回崩れた。**

| いつ | 何が起きたか | どう見つかったか |
|---|---|---|
| **8/29** | **提出した 5.0.1 の現物が HF にも JAIST の機械にも無く、Mac にだけあった。**同じ日に別の GPU 機でも 5.0.1 を組んでおり、**中身は 582 エントリ対 541 エントリ**（差は幾何モデルの同梱ソース 41 ファイル）で sha256 が違った | 提出物を探すのに 3 台を当たった |
| **9/7〜9/11** | **9/7 に組んで出さなかった zip と、9/11 に組んで Track3 へ出した zip が、どちらも 14.0.0 だった。**あとから `work/` に残っていた前者を見て、提出物の中身を誤って書いた文書ができた | 採点ログの起動行（`samples=1`・`adaptive` の欄なし）と、書かれた中身が合わなかった |

**どちらも「名前が同じなら中身も同じ」と読んだことが原因である。**

| 決まり | なぜ |
|---|---|
| **zip を組む作業は 1 台に固定する** | 2 台で組むと、同じ手順でも同梱物が変わる |
| **組んだ zip は、台帳に 1 行書く・HF へ上げる・その場で消す、のどれかに必ず振る** | どこにも振らないと「どこかにあるはず」になる |
| **出さなかった zip にも版番号を使い回さない** | 使い回すと、残った方が提出物に見える |
| **採点された中身は、ファイル名ではなく採点ログの起動行と sha256 で読む** | 9/1 の Track2 のログはファイル名が 5.2.0 だったが、起動行は 8.0.0 だった |

## 2. 同じ状態を何か所にも書くと古い行が残る

**「どの提出が何点だったか」「GPU は空いているか」は、時間とともに変わる状態である。**
複数の文書に書き写すと、どれか 1 つが必ず古くなる。

| いつ | 何が起きたか | 決めたこと |
|---|---|---|
| **9/1** | **1 つの提出の結果が 8 か所に書かれていた**（ユーザの指摘）。読む側はどれが正本か分からない | **提出結果の中身は実験台帳 [reference/19](../reference/19_weights_catalog.md) の 1 か所にだけ書き、他はリンクだけにする** |
| **9/10** | **着手中の作業の板に「GPU は空いている」という古い行が残っていて、学習を二重に起こしかけた。**その機械は 20 GB で、学習 1 本が 16.3 GB を使うので、2 本は同時に載らない | 状態の行は、上書きする板 1 枚だけに置く。**起こす前に `nvidia-smi` で現物を見る** |

**板が本来の置き場（一時ファイルの置き場）ではなく、長く残す事実の置き場に置かれていたことも遠因だった。**
長く残す文書から一時的な板を指すと、板が古くなってもリンクが生き続ける。

## 3. 別のセッションへ依頼を渡すとき

**判断する側のセッションが文脈を抱えすぎないよう、具体的な作業を別のセッションへ依頼として渡した。**
**受け側は聞き返せない**——こちらの会話も、いま何を測っているかも見えない。
だから依頼は **1 ファイルだけで作業が終わる形**にし、次の順に書いた。

| 節 | 中身 |
|---|---|
| **背景**（いちばん先） | どのトラックの話か・いまの点と上位の点・どのデータで測るか・**すでに外したこと**。**背景が無いと、受け側は指示の字面どおりにしか動けない** |
| 何をしてほしいか | 1〜2 行。成果物の形（ファイルか数値か判断か）を名指しする |
| なぜ要るか | **この結果がどの判断を変えるか。書けない依頼は出さない** |
| 前提となる事実 | 受け側が知らない数値と場所。**数値はリンクではなく本文に書き写す** |
| やること・できあがりの条件・やらなくてよいこと | 受け側が自分で終わりを判定できる形にする |
| 判断が必要になったら | **目的に照らしてより良い測り方を思いついたら変えてよい**と書き、変えた理由を報告させる |

**踏んだ穴が 2 つある。**

| 穴 | 対処 |
|---|---|
| **沈黙して失敗する穴は、受け側が自力で気づけない。**自作データの指示文の穴（[23](23_self_made_demos_need_the_instruction_the_model_sees.md)）は、学習が通り損失も下がるので、受け側からは「作ったのに効かない」にしか見えない | **データを作る依頼には、その穴と検査のコマンドを必ず書く** |
| **依頼文を書く費用がこちらに来る。**3 本の依頼で約 1 万 8 千字を書いた | コンペの概要のような共通の背景は 1 ファイルにまとめてリンクし、依頼には差分と数値だけを書く |

**依頼と報告は同じファイルに書き、閉じたら中身を長く残す置き場（実験台帳・手順書・この knowledge）へ移してから消す。**
残しておくと、同じ数値が 2 か所にあって毎回どちらが正かを確かめることになる（2 節）。

## 4. 子エージェントに任せてよいもの

**子エージェントは親と同じ機械・同じ権限で動く。**だから境目は権限ではなく作業の性質で決めた。

| 任せられる | 任せられない |
|---|---|
| 読む・数える・突き合わせる（採点ログの再読・`meta/info.json`） | GPU を使う学習と評価（その機械は他の実験と取り合う・`docker run` が通らない） |
| 小さな道具を書いて置く | **ユーザに聞き返すこと** |
| web を読んで調べる | 提出・zip の組み立て |

| 落とし穴（実際に踏んだもの） | 対処 |
|---|---|
| 子の報告は親の文脈にしか残らず、要約で消える | **必ずファイルに書かせる** |
| 同じファイルを 2 体が書くと壊れる | 1 ファイル 1 書き手。台帳と板は親だけが触る |
| 並行して `git commit` すると `index.lock` で落ちる | 子は commit しない |
| 大きな重みを 2 体が同時に落とすとディスクが埋まり、書きかけのファイルが 0 バイトになる | 大きい取得は 1 体ずつ |
| 重い集計を並べると、2 コアの機械で走っている評価を殺す（実際に 1 本殺した） | 重いものは 1 本ずつ |
| **子の報告が間違っていた**（「設定は一致している」が誤り） | **数値には、それを出したコマンドを添えさせる。結論を変える数値は親が引き直す** |

## 5. 借りた GPU で失ったもの

**自分で管理していない機械は、こちらの都合と関係なく止まり、消える。**

| 失ったもの | 何が起きたか | 決めたこと |
|---|---|---|
| **学習ログ** | **`bowl5_full`（9/12〜13・配布 GPU）は、ログを回収する前にマシンが落ちた。**所要時間も 1 歩の秒数も分からず、重みの sha256 も手元で計算し直した値しか残っていない | **チェックポイントを上げるループが、学習ログも一緒に上げるようにした**（コミット `1f7aacd`） |
| **学習の最初の 18 歩** | コンテナに `--shm-size` を渡しておらず共有メモリが 64 MB になり、データ読み込みの worker が落ちた。**それ以前の 3 本も 64 MB で走っていて、運で通っていた** | 起動スクリプトに `--shm-size=8g` を足した（`solution/train/jaist_launch.sh`） |
| **ログインのトークンとデータ** | 配布 GPU の `~/.cache` と `~/data` は、セッションが終わると消える領域への symlink だった | トークンは `$HOME` の実体に置き、データを展開し直す段取りをスクリプトに畳んだ |
| **端末ごと落ちた学習** | `nohup` は SIGHUP しか防がず、端末が落ちるとプロセスグループごと殺される | **`setsid nohup`** で別のセッションにする |
| **成否の判定** | 学習の入口のスクリプトが、成功しても終了コード 120 を返した | `&&` で後続を繋がず、ログの終了行と成果物の大きさで判定する |
| **GPU の時間** | 配布 GPU の 60 時間は計算時間ではなく起動時間で、セルが動いていれば 12 時間止まらない（本選資料 v1.1 p15） | **起動するのは、デバッグの済んだジョブを始めるときだけにする** |

**配布 GPU で実際に測った値と罠の一覧は [reference/27](../reference/27_blackwell_environment.md) にある。**

## 7. Claude 側

**状態を表す 1 行（「GPU は空いている」「14.0.0 はこの zip」）を読んだら、書かれた日付と現物を突き合わせる。**
名前やパスは人と別のセッションが付け替えるので、**sha256・起動行・`nvidia-smi` のような現物で確かめる。**

**子エージェントや別のセッションの報告を、そのまま結論に使わない。**数値にはコマンドを添えさせ、
結論を変える数値だけは自分で引き直す。

## 8. 人間側

**「同じ数字が 8 か所にある」というユーザの指摘が、台帳を 1 か所に寄せる決まりを作った。**
分担が増えるほど、**正本を 1 つに決めてリンクで指す**ことの値打ちが上がる。

**実行名は「何と 1 変数か」が読める名前にする。**9/10 に、学習率の高さを表す `_hi` という名前を、
比べる相手と同じ土俵の 1 本だと分かる `pi05_v2_base24k` に変えた（ユーザの指示）。
**名前が比べ方を間違えさせる。**
