## 1. 学習・推論時の工夫点および試行錯誤

### 1.1 ステップ数の上限が成否を分けるため、施策の採否をステップ数で判断した

エピソードは 300 ステップで打ち切られ、成功したエピソードは参照デモの 0.96 倍の
ステップ数を要していた。**方策に余裕がなく、わずかな遅延がそのまま未完了に変わる。**
一方で実行時間は 1 時間の上限に対し 32 倍の余裕があり（110 秒）、制約になっていない。
**「ステップ数」と「実時間」は別の量である。**

そこで採点ログから 8 エピソードの合計ステップ数（`/act` の呼び出し回数）を取り出し、
総合スコアと突き合わせたところ、**両者は強い負の相関を示した。**自己評価の成功率では
判定できなかった 2 つの変更（下表 2 行目と 4 行目。**自己評価ではともに 25→28 件へ改善**）が、
ステップ数では明確に分かれる。評価タスク・初期状態・乱数シードは提出間で固定のため、
各行は**1 つの要素だけを変えた対照**である。

| 変えた要素 | 合計ステップ数 | 総合スコア |
|---|---|---|
| Action chunk 長 10 → **16** | 1,428 → **1,142（−20%）** | 0.177 → **0.264（+49%）** |
| chunk 境界の平滑化を追加 | 1,142 → **1,471（+29%）** | 0.264 → **0.169（−36%）** |
| 指示文の正規化を追加（**重みは不変**） | 1,922 → **1,617（−16%）** | 0.166 → **0.181（+9%）** |
| **重みを全パラメータ学習後のものへ** | 1,142 → **991（−13%）** | **0.264 → 0.485（+84%）** |

この基準により、施策の採否が一意に定まった。

- **採らない（ステップ数が増える）**: chunk 境界の平滑化と Real-Time Chunking。
  いずれも境界で直前の計画へ引き戻す機構で、動作が前進しない。RTC は自己評価で
  成功 8→4・ステップ数 +39.5% となったため提出しなかった。
- **採る（実時間のみ消費）**: 推論ステップ数の増加、chunk の複数サンプリング。

### 1.2 Action chunk 長の最適値は、モデルの能力とともに大きくなった

| モデル | 最適な chunk 長 | 根拠 |
|---|---|---|
| SmolVLA (0.4B) | **2〜5** | 50→10→5→2 で単調改善、1 で悪化（0.166→0.080） |
| **π₀.₅ (4.14B)** | **16** | 10→16 で 0.177→0.264。32 は自己評価で 36 件中 13 件が打ち切り |

短すぎる chunk は境界ごとに別のモードを引いて動作が不連続になり、長すぎる chunk は
開ループ区間が伸びて応答性を失う。**モデルを差し替えたら chunk 長は測り直す。**
前モデルの最適値 2 を流用していれば 0.264 には届かなかった。

### 1.3 配布 notebook が凍結している視覚エンコーダまで学習した

配布された学習用 notebook は `freeze_vision_encoder=true`・`train_expert_only=true` で
行動側のみを更新する。段 1 はこれに倣ったが、**18,000 ステップ以降 loss が
0.2375 → 0.2352 → 0.2360 と頭打ちになった。**残存誤差が凍結側にある可能性を考え、
段 2 では視覚エンコーダを含む全パラメータを解いた。**loss は 0.2100 まで低下し（−11%）、
打ち切り時点でも下降が続いていた。**本番スコアは 0.264 → 0.485、合計ステップ数は 13% 減少した。

### 1.4 その他

- **指示文の正規化**: 評価が与える指示文が学習データの表記と異なるため、学習データ側の
  40 種のうち最も近い表記へ寄せた。**重みを変えずに 0.166 → 0.181。**
- **自己評価の上限**: 初期状態の復元直後に物体が落下し、方策の動作前に衝突判定が成立する
  事例が 2 件あった（複数モデルで変位が同一）。方策側では回避できないため、自己評価の
  上限を 34/36 として扱った。

## 2. モデル情報

| 項目 | 内容 |
|---|---|
| モデル名・バージョン | `policy_server` **4.2.0** |
| ベースモデル名 | **π₀.₅ (Pi05)**（Physical Intelligence／LeRobot 実装） |
| ベース重みの入手元 | Hugging Face **`lerobot/pi05_libero_base`** |
| 重みの revision | **`a217bfd3b14673cf2ce597e69997ab21866438dd`** |
| 提出 zip の SHA-256 | **`5cf6b9836f46805ba10bdde93ead02913c65d050adfb20d6800a3788b4cdb9ee`** |
| チェックポイントの SHA-256 | `0c5d542e0052863a7d2caba141c076003b82d3156cd355654e4ba72cc8edfe6d`（`model.safetensors`） |
| モデル構成 | Vision-Language-Action。総パラメータ **4,143,404,816**（safetensors テンソル 813 個） |
| 推論方式 | **Flow matching**、ノイズ除去 **10 ステップ** |
| **Action chunk** | **有り。長さ 50 を生成し、先頭 16 ステップを実行して再生成** |
| 後処理 | 直前行動との EMA 平滑化（係数 0.3、姿勢 6 次元のみ。グリッパは対象外）、指示文の正規化 |

推論時の構成は、採点ログの先頭行として出力される。

```
policy_server 4.2.0  model=pi05  num_inference_steps=10  n_action_steps=16
ema_alpha=0.3  blend_steps=0  samples=1  rtc=off  normalize=on
```
