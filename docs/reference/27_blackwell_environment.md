## 2. 学習の速さの実測（batch 64）

**π0.5 のフルパラメータ学習（4,143,404,816 パラメータ）を batch 64 で回したときの値である。**

| 項目 | 値 |
|---|---|
| **1 歩** | **6.85 秒**（`updt_s` 6.840 ＋ `data_s` 0.007） |
| 同じ学習の A100 80GB | 10.05〜10.24 秒 → **Blackwell は 1 歩あたり 33% 速い** |
| `mem_gb` | **49.40**（95.0 GB のうち。**batch 64 は余裕で載る**） |
| モデルの読み込み | **約 2 分**（`Creating policy` から `Start offline training` まで） |
| 学習データの取得 | **83 ファイルを 50 秒**（`HF_HOME` に残るので同じセッション内で 2 度目は無い） |
| チェックポイントの保存 | **21 秒**／個 |
| チェックポイント 1 個の大きさ | **8.8 GB**（`pretrained_model`。全体では 25 GB） |
| 2,500 歩を 1 本 | **4 時間 48 分 23 秒**（11:46:52 → 16:35:15・終了コード 0） |

**1 歩の秒数は `updt_s` と `data_s` の足し算である。**lerobot 自身が同じ足し方で残り時間を
出している（`src/lerobot/scripts/lerobot_train.py` 603 行）。

**環境構築に消えた分。**8/31 の 1 本目は**セッション全体で約 7 時間**を使い、
**そのうち学習は 4 時間 48 分**だった。差は環境構築である。
**2 回目以降は venv が `$HOME` に残るので、この差はほぼ消える。**

## 3. パスの実体 —— `$HOME` の 3 つは symlink で、消える領域を指す

**`ls -lka ~` で確認した（8/31）。**

| symlink | 先 | 意味 |
|---|---|---|
| `~/data` | `/opt/dlami/nvme/data/<アカウント名>` | **消える領域の上にある。**`parc-home-sync data-push` を打った分だけが残る |
| `~/.cache` | `/opt/dlami/nvme/cache/<アカウント名>` | **消える。**だから `hf auth login` が書くトークン（`~/.cache/huggingface/token`）も毎回消える |
| `~/dataset` | `/opt/parc/dataset` | **配布データセットの実体。**読み出し専用で消えない |

**どれも `$HOME` の自動保存には乗らない**——保存されるのは `$HOME` の実体だけである。
**だから HF のトークンは `~/.hf_token`（実体が `$HOME`）に置く。**

**`$HOME` の中身は root 所有である**（同じ `ls`）。書けているので実害は無いが、
**`chown` を前提にした手順は書けない。**

**`$HOME` の容量は確定していない。**資料 v1.1 p14 は **40 GiB** と書いているが、
**8/31 の実測は 98 GB だった**（`open_items.md` の `F53`）。**小さいほうを前提に置く。**

**何をどこへ置くかは、これで決まる。**

| 置くもの | 大きさ | どこへ | なぜ |
|---|---|---|---|
| venv ＋ lerobot ＋ python3.12 | **約 8.5 GB** | **`$HOME`** | 自動保存されるので作り直さなくて済む |
| 学習データと HF のキャッシュ | 15.83 GB | `/opt/dlami/nvme/hf_home` | `$HOME` の枠を食い潰さない |
| 学習の出力（1 個 11 GB） | | `/opt/dlami/nvme/out` | **セッション終了で消えるので、HF へ上げるまでが勝負** |
| 出発点の重み（1 個 8.8 GB） | | `/opt/dlami/nvme/weights` | **毎セッション HF から降ろし直す。**`$HOME` に置く案は 6 節 |
| 数えた結果のテキスト | | `~/`（`$HOME`） | 自動保存で残る |

**`~/dataset` は消えないので、配布データを HF から落とし直す必要は無い**——
2 回目以降のセッションでも、そこの tar を `~/data` へ展開し直すだけで済む（資料 v1.1 p19）。

## 4. 通算歩数と出力の名前はずれる

**`--init-from` は歩数のカウンタを引き継がない。**だから**出力は必ず `000500`・`001000`… から始まる。**

**`001500` から続けた場合、出力の `000500` は通算 `002000` である。**
**HF へ上げるときに通算の名前へ直すこと**——直さないと `pi05_trial1500` の `000500` と
区別できなくなる。

**あわせて、`--init-from` は学習率の刻みも引き継がない。**
`--learning-rate` を省くと頂点 2.5e-5 に戻り、**前の学習が 2.5e-6 で終わっているぶんの 10 倍**から
再スタートする（`load_training_state` が読む `training_state/` は `--resume` のときだけ使われる。
`lerobot/scripts/lerobot_train.py` 385〜389 行・`lerobot/common/train_utils.py` 201 行）。
**歩数を足しても学習量は足し算にならない**理由がこれである
（[19_weights_catalog.md](19_weights_catalog.md)）。

## 5. 踏んだ罠（実際に 1 度は踏んだもの）

| 罠 | 中身と対処 |
|---|---|
| **`train_pi05.py` は成功しても終了コード 120 を返す** | 8/31 の 60 歩で実測。`[train_pi05] === 終了（終了コード 0）===` を出したあと、`_Tee.flush` が閉じた stdout を flush しようとして `ValueError` になり、python が 120 で終わる。**`&&` で後続を繋がないこと。**判定は**ログの `終了（終了コード 0）` の行と、成果物の `du -sh` で行う** |
| **Notebook のセルが `/bin/sh` で動くことがある** | `source` が無い。**`.` で読む** |
| **認証していないと非公開リポジトリが `not found` に見える** | `pi05_full_runpod`・`pi05_trial1500`・`pi05_code` は**3 つとも非公開**で、HF は未認証の相手に「無い」と答える。**名前の間違いではない** |
| **`~/.hf_token` に説明文をそのまま貼ると `'ascii' codec can't encode`** | 8/31 に実際に起きた。**そのせいで修正版のスクリプトも降りて来ず、直したはずの不具合がもう一度出た。**`hf_` で始まる英数字だけの 1 行にする |
| **カスタム Docker は使えない**（資料 v1.1 p14） | `$HOME` の venv に作る。**配布イメージの `docker run` は提出前の最終確認にだけ使える** |
| **学習のチェックポイントに `vlm/` は付かない** | 評価も zip も落ちる。`rp3000` から `cp -r` する（`ln -s` は駄目）。**ただし HF の `pi05_trial1500` の重みには `vlm/` が同梱されている**ので、そこから降ろす分は要らない |
| **`df` が答えない共有ストレージがある** | 使用量は `du -sh`、枠は画面で見る |

**2026-09-07〜09-08 に、逆向きデータを混ぜて 1 本回したときに踏んだもの。**
**この段取りは `solution/train/blackwell_setup.sh` と `blackwell_launch.sh` に畳んである**
（[howto/14 の B3b](../howto/14_blackwell_session.md#b3b-98-に作った段取りを-2-本のスクリプトに畳んだ)）。
**スクリプトはこれらを全部その場で捕まえて、原因と次の一手を出して止まる。**

| 罠 | 中身と対処 |
|---|---|
| **サーバは UI からしか止められない** | **`JUPYTERHUB_API_URL` への `DELETE` は効かない**（9/8 に確かめた）。`File > Hub Control Panel > Stop Server` を押す |
| **`/opt/dlami/nvme` の中身が消えている**（`$HOME` は残る） | **インスタンスが入れ替わると消える領域である**（3 節）。配布データ・混ぜたもの・出発点の重みは作り直し。**`blackwell_setup.sh` で 5 分** |
| **ターミナルが落ちてシェル変数が消え、`/bin/sh` に落ちる** | 作った物はディスクに残っているので**作り直さない**。`. ~/run_env.sh` で変数を張り直し、`meta/info.json` の本数で出来ているものを確かめる |
| **関数の中の `\|\| exit 1` が対話シェルごと終わらせる** | **`\|\| return 1` にして `&&` で繋ぐ。**手で打つ段取りに `exit` を書かない |
| **落ちるターミナルから長い学習を起こす** | **`nohup` は SIGHUP しか防がない。**プロセスグループごと殺されるので **`setsid nohup`** で別セッションにする |
| **`hf download` は `$HOME` に置かない** | HF キャッシュの `hub/<repo>/snapshots/<sha>/` に入る。`find "$HF_HOME/hub" -name <file>` で拾う。**データセットには `--repo-type dataset` が要る** |
| **`~/pi05_code/train_pi05.py` が無い** | **`siruku6/pi05_code` は入れ子である。**実体は `~/pi05_code/solution/train/train_pi05.py` |
| **`No module named 'scripted_demo'`** | `npz_to_lerobot.py` だけ渡しても動かない。**隣に `scripted_demo.py` を並べる**（`sys.path` に自分の隣が入る） |
| **`merge` が `av.error.FileNotFoundError: .../file-000.mp4` で落ちる** | **配布 tar の動画の通し番号は 6 桁**だが、`aggregate_videos` はデータセット自身の `video_path` を見ず **lerobot に焼き込まれた 3 桁だけ**を使う。`solution/tools/track3_reversal/link_video_index_width.py --root "$DATA"` で 3 桁の symlink を張る（info.json は触らないので配布データを直接学習に使う道は壊れない） |
| **`align` が `observation.images.front の形が違う` で止まる** | **軸名の綴りが違うだけ**（配布は `rgb`・こちらは `channel`）。9/7 に `_feature_shape` から `names` を外した。**形（dtype と shape）は今も厳格に見る** |
| **`merge` をやり直すと `に中身がある` で止まる** | `_prepare_output` は空でないと止まる。**書きかけの出力を消してから打つ** |
| **`--save-freq` を歩数より大きくしてもチェックポイントは書かれる** | `End of training` の直前に 1 個（8.8 GB）。**試走のあとは消す** |

## 6. まだ測っていないこと

**根拠が弱いまま前提にしているものを、分けて書いておく。**

| 測っていないこと | 外れたらどうなるか |
|---|---|
| **`$HOME` の復元にかかる時間** | 2 回目のセッションの起動が長ければ、`$HOME` に置くものを減らすほうが速い。**出発点の重み 8.8 GB を `$HOME` に置いて HF の往復を消す案は、これが測れるまで保留である** |
| **`nohup` のプロセスがセルの終了後も生き続けるか** | 死ぬなら、学習を監視セルの中で動かす形に変える（ただしセルが切れると学習も死ぬので、保存間隔を詰めることになる） |
| **HF の非公開の枠の空き** | 8/29 に数えた 67.03 GB（空き約 33 GB）を基準にしている。**チェックポイント 1 個が 8.8 GB なので、500 歩ごとに全部上げると入らない** |
