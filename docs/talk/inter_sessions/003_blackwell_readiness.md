# 003 Blackwell が開いた瞬間に学習を始められる状態にする

> **状態: 依頼中** ／ 受け側: 未定 ／ 更新: 2026-08-28

## 何をしてほしいか

**Blackwell サーバで 9,000 ステップのフルパラメータ学習を回すための段取りを、
「セッションが切れても続きから再開できる」形まで作り込んでほしい。**
成果物は **(1) Notebook に貼るセルの列** と **(2) 中断・再開の手順**である。

## なぜ要るか

**時間の上限に、いまの計画が収まっていない。**

| 制約 | 値 | 出典 |
|---|---|---|
| 本選 1 の期間全体で使える時間 | **60 時間** | `docs/howto/14_blackwell_first_session.md` |
| **1 セッションの上限** | **起動から 12 時間で自動停止** | 同上 |
| 何も実行していないときの自動停止 | 1 時間 | 同上 |

**9,000 ステップは 25.8 時間かかる**（1 回目のフルパラメータ学習の実測 6.2 samples/s、
batch 64、9,000 × 64 ÷ 6.2 = 92,903 秒）。**12 時間の枠に入らない。**
**Blackwell が速くて 2 倍出たとしても 13 時間で、まだ入らない。**

**だから「途中で切れても続きから」が成立しないと、この計画そのものが回らない。**
ここが作れているかどうかが、9,000 ステップをやるかどうかの前提になる。

## 前提となる事実

**自分の Docker イメージは持ち込めない。** 2026-08-26 の資料 v1.1 でサポート外になった
（`docs/howto/14_blackwell_first_session.md`）。**Notebook の Python 環境へ直に pip で入れる。**
使える `docker run` は Omnicampus 提出の事前チェック用のものだけである。

**学習の中身は決まっている。** `docs/plan/15_runpod_fullparam_with_augment.md` にある。

```bash
python train_pi05.py --run-name pi05_full2_aug \
    --init-from <出発点の重み> \
    --camera-viewpoint-augment \
    --steps 9000 --batch-size 64 --num-workers 16 \
    --learning-rate 5e-6 --save-freq 1500 \
    --freeze-vision-encoder false --train-expert-only false
```

**起動直後に必ず確かめる 1 つ。** ログの `num_learnable_params` が
**4143404816** であること。**693422112 になっていたら行動側しか学習していない**ので、
その場で止める（`--train-expert-only` が効いてしまっている）。

**`compile_model` は `false` のままにすること。** `true` だとチェックポイントに焼き付き、
評価サーバの起動が 1,177.9 秒かかって落ちる。

**出発点の重み。** `work/artifacts/pi05_rp3000`（フルパラメータ 3,000 歩・8/17・
RunPod A100 80GB・8 時間 33 分）。**手元にあり、HF の私有リポジトリにも上げてある。**

**コードの持ち込み方。** HF の私有リポジトリ経由が速い。`runpod_code_260827.tar.gz`
（46 KB）という前例があり、手順は `docs/plan/15_runpod_fullparam_with_augment.md` にある。
**scp は 1.7 MB/s しか出ないので、大きいものには使わない。**

## やること

1. **中断と再開の道を決める。** ここがこの依頼の中心である。次を満たすこと。
   - **チェックポイントと optimizer の状態が、セッションが消えても残る場所に置かれる。**
     Blackwell の永続化の道具が何かは下見（`howto/14` 手順 1）で分かる。
     **分からなければ HF の私有リポジトリへ上げる形で設計してよい。**
   - **再開したとき、ステップ数・学習率のスケジュール・データの順序が続きになる。**
     **学習率が最初からやり直しになると、9,000 ステップぶんの意味が変わる。**
     LeRobot のどの仕組みで再開するのかを、`/opt/lerobot` のコードで確かめて書くこと。
   - **1 回のセッションで何ステップ進むかを見て、`--steps` と `--save-freq` を決める。**

2. **貼るだけのセルの列にする。** 下見・pip・コードの取得・重みの取得・学習の開始・
   チェックポイントの退避、の順。**1 セル 1 目的にして、途中から流せるようにする。**
   `notebook-runbook` スキルがあるので、それに沿うこと。

3. **時間の見積もりを表にする。** 60 時間のうち何を何時間使うか。
   **下見・環境作り・重みの往復に何時間持っていかれるかを、学習の時間と分けて書く。**

4. **`docs/howto/` に置く。** 既存の `14_blackwell_first_session.md` は下見の手順なので、
   **学習の手順は別の節か別ファイルにする。**どちらにするかは受け側が決めてよい。

## できあがりの条件

- **セッションが 12 時間で切れた次に、何を打てば続きから始まるかが 1 行で書いてある**
- 60 時間の使い道が表になっている
- `num_learnable_params` の確認が手順に入っている

## 報告の書き方

1. **再開の仕組み**——何を保存し、何を打つと続くか。**5 行以内で。**
2. **60 時間の割り振りの表。**
3. **9,000 ステップが 60 時間に収まるかどうかの判定。**収まらないなら何ステップなら収まるか。
4. **危ないところ 3 つ**——失敗したらどう気づくかを添えて。
