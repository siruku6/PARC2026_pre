# 002 ロボット初期姿勢の振り方を、作業空間を覆う形に作り直す

> **状態: 依頼中** ／ 受け側: 未定 ／ 更新: 2026-08-28

## 背景（先に読んでほしい）

**このコンペで何をしているか。** PARC2026 の本選 1 である。ロボット（Franka Emika Panda）に
自然言語の指示を与え、LIBERO-plus のシミュレータの中で物を掴んで運ばせる。
こちらの方策は **π0.5**（41 億パラメータ）である。

**この依頼が効くのは Track2 である。**

| トラック | 中身 | こちらの点 | リーダーボードの最高 |
|---|---|---|---|
| Track1 | 学習済みタスク・**背景と照明**が変わる | 0.370 | 0.65 |
| **Track2** | 学習済みタスク・**視点・ロボットの初期姿勢・物の配置・センサ雑音**が変わる | **0.207** | **0.53** |
| Track3 | 見たことのないタスク | 0.000 | 0.000（全参加者） |

**Track2 で何が出るかは非公開である。** LIBERO-plus には摂動が 7 カテゴリあり、
Track1 で使われない 4 つ（カメラ視点・ロボット初期姿勢・物の配置・センサ雑音）が
Track2 に対応すると読んでいる。**この 4 つのうちどれに学習データを寄せるかが、
残り 20 日の学習計画を決める。**

**すでに決まっていること。** 物の配置（歩数 +6.1%・p = 0.388）とセンサ雑音（+9.8%）は
**回し直しのばらつき（±6.5%）の内側かすぐ上**なので、投資の対象から外した。
**カメラ視点は効く**（2026-08-28 の 216 本で、所要時間が Base 比 +25.4%／+14.2%）。
**残る 1 つがロボットの初期姿勢で、そこだけ結論が割れている**——それがこの依頼である。

**なぜ「作業空間を覆う」が要るのか。** 公式の 500 通りは
**たった 1 つの基準姿勢のまわりのゆらぎ**である（下の `new_init.py` を見てほしい）。
**本番でどう振られるかは分からないが、「基準姿勢のまわりだけ」で学習データを設計すると、
覆えていない範囲で落ちる。**理想は、**タスクが成立する範囲で作業空間全体に散らす**ことである。

**測る対象のデータ。** 比べる相手は `compe/val/TRACK2_VAL72.csv` の
`category` が `Base` の 12 行（摂動なし）。この 12 タスクは、摂動なしで 3 回とも
打ち切り（300 歩）に達しなかったものを選んである。

**判断が必要になったら。** この依頼の目的は「学習データをロボット初期姿勢に寄せるべきか、
寄せるならどの範囲か」を決めることである。**その目的に照らして、より良い測り方を
思いついたら変えてよい。**変えた場合は理由を報告に書くこと。

## 何をしてほしいか

**「ロボットの初期姿勢が変わると方策がどれだけ崩れるか」を、作業空間を覆う形で測り直してほしい。**
成果物は **(1) 初期姿勢の作り方（コード）** と **(2) 崩れ方の表**である。

## なぜ要るか

**測り方が 2 通りあって、答えが逆に出ている。学習データを何に寄せるかがこれで決まる。**

| いつ | 測り方 | 結果 |
|---|---|---|
| 8/24 | LIBERO-plus の公式一覧から Robot 変種を 12 個（タスクごとに別の姿勢） | **歩数 +47.8%・12 タスク中 6 つを壊した。最悪の軸** |
| 8/28 | 姿勢の番号を 50・150・350 に固定し、12 タスクへ同じものを当てた | **所要時間 −4.1%〜+6.9%。効かなかった** |

**8/28 の設計に穴がある。**摂動は「単位ベクトル × 倍率」なので、番号が変わると**向きが変わる**。
**8/28 は 1 段階につき 1 つの向きしか見ていない。**優しい向きを 3 つ引いた可能性がある。

**さらに、公式のやり方そのものが狭い。** 下の「前提となる事実」のとおり、
LIBERO-plus の 500 通りはすべて**たった 1 つの基準姿勢のまわりのゆらぎ**であって、
作業空間を覆っていない。**本番でどちらが出るかは分からないが、
「基準姿勢のまわりだけ」で学習データを設計すると、覆えていない範囲で落ちる。**

## 前提となる事実

**公式の摂動の作り方は `work/LIBERO-plus/libero/libero/envs/robots/new_init.py` にある。**
中身はこうである（i は 1〜500）。

```python
np.random.seed(42)
original_qpos = np.array([0.0, -1.61037389e-01, 0.00, -2.44459747e00,
                          0.00, 2.22675220e00, np.pi / 4])
perturbation = np.random.randn(7)
perturbation = perturbation / np.linalg.norm(perturbation)   # 単位ベクトル
perturbed_qpos = original_qpos + perturbation * 0.1          # 倍率
```

**倍率は番号で決まる。** 1〜100 → 0.1、101〜200 → 0.2、201〜300 → 0.3、
301〜400 → 0.4、401〜500 → 0.5。**単位は関節角のラジアンで、7 軸あわせた大きさである。**

**押さえるべき 3 点。**

1. **基準姿勢は 1 つしかない。**500 通りは全部そのまわりである。
2. **手先の位置ではなく関節角を振っている。**同じ大きさでも向きによって手先の動き方が違う。
3. **ロボットの土台は動かない。**置き場所の話ではない。

**変種名の書き方。** タスク名の後ろに
`_view_<方位角>_<仰角>_<拡大率×100>_<レンズ回転>_<レンズ上下>_initstate_<番号>` を付ける。
**一覧に無い組み合わせを自分で書いてよい**——環境が存在を確かめるのは `_view_` より前の
`.bddl` だけである（`work/LIBERO-plus/libero/libero/envs/env_wrapper.py:207-237`）。
姿勢だけを変えるなら `_view_0_0_100_0_0_initstate_<番号>` になる。

**`if int(init_state) != 0: robots = [robots[0] + str(init_state)]`** という実装なので、
**番号は `new_init.py` が作った 1〜500 のクラスに限られる。**
501 番以降や、独自の姿勢を使いたい場合は**クラスを足す必要がある**（下の「やること」2）。

**比べる相手にする 12 タスク。** 8/24 に Base が 3 回とも 300 歩未満で完走したものである。
`compe/val/TRACK2_VAL72.csv` の `category` が `Base` の 12 行がそれで、そのまま使える。

**評価の回し方。** `solution/tools/eval/run_final_eval.sh` に `TASKS_CSV` があり、
こちらの CSV を配布キットの CSV の上にマウントして回せる。

```
TASKS_CSV=<CSVのパス> TRACK_EPISODES=3 MUJOCO_GL=egl \
  PARC_N_ACTION_STEPS=16 PARC_EMA_ALPHA=0.3 LABEL=<名前> \
  solution/tools/eval/run_final_eval.sh track2
```

**回すのは会社の RTX6000 で、ユーザが打つ。**このマシンからは `docker run` が通らない
（組織の制約・解除不可）。**1 ロールアウトあたり約 18 秒**なので、本数から時間を見積もって
依頼すること。**200 本を超える依頼は、先に理由を報告に書くこと。**

## やること

1. **まず、公式の 500 通りで手先がどれだけ動くかを数える。**
   関節角から手先の位置を出し（順運動学）、**基準姿勢の手先からの距離の分布**を出す。
   倍率 0.1〜0.5 のそれぞれについて、中央値と最大値。
   **これで「基準姿勢のまわり」がどれくらいの広さなのかが数字になる。**

2. **作業空間を覆う初期姿勢を作る。**
   **同じ大きさでも向きで効き方が変わる**ので、**向きを揃えて散らす**。
   最低限、次の 2 つを満たすこと。
   - **12 タスクそれぞれに別の向きを当てる**（8/28 の穴を塞ぐ）
   - **手先の位置で見て、基準からの向きが偏らないようにする**（上下・左右・前後）

   **公式の 1〜500 から選ぶだけで足りるならそれでよい。**
   足りないなら `new_init.py` と同じ形でクラスを足す。**足した場合は、
   足したことと足し方を報告に書くこと。**

3. **タスクが成り立つかを先に確かめる。** 姿勢によっては初手から物に触れていたり、
   腕が机に埋まっていたりする。**方策を動かす前に、その姿勢で環境が作れて、
   何もしないで 10 ステップ進めたときに衝突判定が立たないことを確かめる。**
   **通らない姿勢は落とし、落とした数を報告する。**

4. **評価用の CSV を作り、ユーザに回してもらう。** 置き場所は `compe/val/`。
   名前は中身が分かるものにする。

5. **崩れ方を出す。**

## できあがりの条件

- 1 の分布が出ている
- 使った姿勢が、タスクごとに違う向きになっている
- 通らなかった姿勢の数が分かっている
- 下の表が書けている

## 報告の書き方

1. **公式 500 通りの手先の広がり。**倍率ごとに中央値と最大値（m）。
2. **新しい集合での崩れ方。**Base と比べて、**成功率・衝突率・全エピソードを含む所要時間の比**。
   **成功時だけの歩数は使わないこと**——落ちた回が除かれて効果が消える。
3. **8/24（+47.8%）と 8/28（ほぼ 0）のどちらに近かったか、1 行で。**

## やらなくてよいこと

- カメラ視点の摂動（効くことは 8/28 に確認済み。所要時間 +25.4%／+14.2%）。
- `NOW.md` の書き換え。
