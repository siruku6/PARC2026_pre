**この結果が変える判断は 1 つ——「逆向きデータで Track3 を動かす道を続けるか、切るか」である。**

いま `pi05_v2_base24k`（v2 のデータ・24,000 ステップ）を回していて、9/10 中に終わる。

## 4. 前提となる事実

**判明した数値そのものは [reference/33](../../reference/33_gradient_norm_and_action_saturation.md)
に置いた**（ユーザの指示で、この依頼には書き写さない）。
**ここには作業に要る 3 つだけを書く。**

### 4.1 直す対象は `osc_command` と、それを呼ぶすべての場所である

`solution/tools/track3_reversal/replay_video_probe.py` の `osc_command`（513 行）は、
**目標姿勢との差を `OUT_MAX` で割って ±1 で切る比例制御**である。
呼び出し元は `move_to`（708 行）・把持（736 行）・上昇・復路（764 行）・
設置（781〜806 行）で、**接近区間だけを直しても足りない。**

上限ちょうどのコマはエピソードの先頭に集中しているが、**相対位置 25〜50% にも
2 割ある**（上昇と復路への合流）。**呼び出し元を全部直すこと。**

### 4.2 守る封筒は、配布データ自身が持っている値である

| `action` の次元 | 配布データが取る範囲 | 配布データが端に乗る割合 |
|---|---|---|
| 並進（0〜2） | **±0.9375**（＝60/64） | 6.40%（1 軸でも） |
| 回転（3〜5） | **±0.375** | 0.54%（1 軸でも） |

**「端に 1 コマも乗せない」ことが目標ではない。配布データと同じ程度に収めることが目標である。**
いまの逆向きデータは並進が **±1.000**（配布に存在しない値）に 20.24%、
回転が ±0.375 ちょうどに 28.81% 乗っている。

### 4.3 一定速度の区間を作ると、上限が別の値に移るだけである

**台形の速度の形（加速 → 一定 → 減速）を使ってはいけない。**
一定速度の区間がそのまま**別の 1 点への積み上がり**になる。
**加速も減速もなめらかで、一定速度の区間を持たない形を使うこと**
（5 次多項式の最小ジャーク＝加速度の変化が最も小さい軌道が素直）。

## 5. やること

**順番がある。1 → 2 → 3 → 4 → 5 の順で、途中で止めてよいのは 2 の後だけである。**

### 5.1 手順 1: 接近を「時刻を決めた軌道を追う」形に書き換える（実装・1〜2 時間）

**いまの `move_to` は「着くまで比例制御で寄る」なので、遠いあいだ指令が上限に張り付く。**
**これを「先に通過点の列を作り、1 コマに 1 点ずつ渡す」形に変える。**

```
関数 approach_waypoints(現在の姿勢, 目標の姿勢, 1 コマに出してよい指令の上限):
    L        ← 現在位置から目標位置までの距離
    theta    ← 現在の向きから目標の向きまでの回転角
    # 最小ジャークの速度の山は、平均速度の 1.875 倍になる
    N_pos    ← ceil(1.875 * L     / (上限_並進 * 1 単位あたりの実移動量))
    N_rot    ← ceil(1.875 * theta / (上限_回転 * 1 単位あたりの実回転量))
    N        ← max(N_pos, N_rot, 最小コマ数)
    for i in 1..N:
        s ← i / N
        w ← 10*s^3 - 15*s^4 + 6*s^5        # 0 → 1 へなめらかに上がる
        通過点[i] ← 現在の姿勢 から 目標の姿勢 へ w だけ進んだ姿勢
    return 通過点
```

**そのうえで:**

1. `move_to` を、上の通過点を 1 コマに 1 点ずつ `osc_command` の `target` に渡す形にする
2. **通過点を配り終えたあと、残った誤差を詰めるために比例制御を数コマだけ回す**
   （いまの `arrived()` の判定をそのまま使う。ここは差が小さいので上限に当たらない）
3. **`osc_command` の `np.clip` と `rot_limit` の縮小はそのまま残す。**
   通過点が正しければ発動しないので、**発動したら設計が間違っているという合図になる**
4. **1 単位あたりの実移動量は当て直すこと。**手元の配布データから最小二乗で当てると
   **11.25 mm/単位**だが、**上限を出し続けた区間ではこれより速く動く**ので、
   実際に回して測った値で合わせ直す

**上限の初期値。**並進 **0.85**・回転 **0.30** から始める。
**配布データの端（0.9375 / 0.375）より内側で、かつ余裕を持たせすぎない値である。**

## 8.5 【9/11 追記】5.1 節の 4「1 単位あたりの実移動量は当て直すこと」の答え

**測り方。**1 コマの実変位を、そのコマの指令のノルムで割った**中央値**を採る。
成分ごとの最小二乗は、止まっているコマに引っ張られて低く出る。

| | 並進 | 回転 |
|---|---|---|
| **配布データ**（ep4061-4063 の順方向） | **12.94 mm/単位** | **0.1153 rad/単位** |
| **自作データ**（逆向き 3 本） | 12.55 mm/単位 | 0.1197 rad/単位 |
| 5.1 節が置いた暫定値 | 11.25 mm/単位 | 0.1125 rad/単位 |

**回転は当たっていた**（上限 0.30 × 0.1125 rad = 1.93°/コマ で、配布データの
1 コマ最大 1.96° とちょうど揃う）。**並進は 14% 低すぎた。**低く見積もると通過点を
刻みすぎ、そのぶんエピソードが伸びて遅くなる。

**上限も上げた（並進 0.85 → 0.9375 ＝ 配布データの端そのもの）。**
0.85 は封筒の内側を取りすぎていて、できたデータは並進 ±0.9375 以上が **0.00%**
（配布は 6.40%、本タスクの 3 本では 10.9%）——**配布より遅い側に外れていた。**
「端に 1 コマも乗せない」ではなく「配布と同じ程度に収める」が 4.2 節の目標である。

**結果**（本 3 本・`T3_INIT=0`）。①〜④はすべて通ったまま、速さとコマ数が改善した。

| 見るもの | 作り直し直後 | **9/11** | 条件 |
|---|---|---|---|
| ① 並進 ±1.000 | 0.00% | **0.00%** | 0.00% |
| ② 並進 ≥0.9375 | 0.00% | **0.00%** | <10% |
| ③ 回転 ±0.375 | 0.00% | **0.00%** | <3% |
| ④ release までのコマ数 | 297 / 283 / 266 | **224 / 228 / 209** | ≤300 |
| 1 コマの変位（中央 / p90） | 5.08 / 7.71 mm | **6.81 / 9.31 mm** | 配布 8.22 / 12.65 |

**残った差。**まだ配布データより遅い。理由は測ってある——配布データは指令の中央
0.611 で 8.22 mm 進むのに、こちらは閉ループで目標を追い直すぶん遅れが乗るので
同じ距離により大きい指令が要る。**通過点の間隔をこれ以上広げると ① が立つ**
（上限 0.9375 のとき復路の最大変位は 12.2 mm で、配布の最大 15.8 mm には届かない）。

**同時に直した「無駄」は [reference/31 の 4・6.2・7 節](../../reference/31_reverse_place_without_contact.md)
に置いた**（合流の橋が荷物を 68° 振り回していた／本が最後に横倒しになっていた／
引き上げる腕が置いた本を叩いていた）。

## 9. こちらが勝手に決めた範囲

**判断を求めない部分を先に示す。**

| 決めたこと | 理由 |
|---|---|
| **複製は ×8 のまま** | 次の学習 1 本を `pi05_v2_base24k` と**データの作りだけの 1 変数**にするため |
| **配布側は `libero_plus` 3,000 本のまま** | v2 と同じ |
| **速度の形は最小ジャーク** | 一定速度の区間を持たない形なら何でもよい。素直なものを 1 つ指定した（4.3 節） |
| **上限の初期値は 並進 0.85・回転 0.30** | 配布データの端より内側。**合わなければ受け側が動かしてよい**（10 節） |

**こちらが撤回した判断も残す。**

| こちらの主張 | 実際 | なぜ間違えたか |
|---|---|---|
| **`grdn` が 1.0 でクリップされているので、実効の学習率が 1/3 になっている**（[reference/32](../now.md) の D-2 の節に 9/10 まで書いてあった） | **ならない。**クリップはノルムをちょうど 1.0 に揃えるので、v2 が受け取る勾配は 1.00 で、切られていない `clean24k`（0.81）より**大きい** | 「クリップ＝縮める」と読み、**揃える操作だと確かめていなかった。**AdamW が勾配の大きさを打ち消すことも見ていなかった |
| **`ROT_LIMIT=0.375` で外れ値を消せば `grdn` は 1 前後に落ちる**（[025 の 4.4.3 節](025_reverse_data_state_and_next.md)） | **2.5〜7.8 → 1.4 までしか落ちなかった** | 外れ値を「消す」ことと「切る」ことを同じだと思っていた。**切ると値は上限の 1 点に集まる** |

## 10. 判断が必要になったら

**この依頼が変える判断は 3 節に書いた 1 つである。**
**その目的に照らして、より良い測り方や作り方を思いついたら変えてよい。**
**変えた場合は理由を報告に 1 行書くこと。**

**特に、次の 2 つは変えてよい前提として書いている。**

1. **1 コマに出してよい指令の上限**（並進 0.85・回転 0.30）。
   **6 節の 4 条件を満たすなら、いくつでもよい。**
2. **速度の形**（最小ジャーク）。**一定速度の区間を持たない形なら何でもよい。**

**逆に、変えるなら先に聞いてほしいのは 1 つだけである。**
**コマ数が 300 を超えるエピソードが出るとき。**落とすか、
`MAX_TAIL`（放したあと腕を引く区間・採点に効かない）を削るかで結果が変わる。
