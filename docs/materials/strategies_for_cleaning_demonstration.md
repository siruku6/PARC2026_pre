# **ロボット操作模倣学習におけるデモンストレーション軌道修復・再生成技術の体系的分析と実装戦略**

## 

## **問題の所在と力学・行動空間における構造的課題**

ロボット操作の模倣学習（Imitation Learning）、とりわけ Vision-Language-Action（VLA）モデルや拡散方策（Diffusion Policy）を実機や高精度物理シミュレータに展開する際、訓練データセットに含まれる軌道の幾何学的整合性と動力学的妥当性は方策の汎化性能を決定づける極めて重要な要因である。先行する実験的検証（026\_contact\_demo\_cleanup、028\_reverse\_approach\_velocity\_profile、030\_data\_side\_levers\_review）において、既存の軌道データに対する「不良データの単純除外（フィルタリング）」および「単純なクリッピングによる速度制限」はいずれも重大な技術的限界に直面している。

第一の構造的課題は、接触や衝突を含むデモンストレーションを除去するフィルタリングアプローチの破綻である。シミュレータ環境における非意図的な接触（対象外物体が 1 mm 以上動く事象）を含むエピソード（全体の約 15%）を除外して学習を行った検証では、評価環境での衝突率は低減せず、むしろタスクによっては成功率が低下する現象が観測された \[cite: 6, 15.2, 16.2\]。この原因は、衝突の主因が「接触動作自体の模倣」にあるのではなく、初期姿勢やカメラ視点の摂動によって方策の手先位置が手本の存在しない未学習領域（Out-of-Distribution, OOD）へ逸脱し、共変量シフト（Covariate Shift）を起こして制御が発散することにある \[cite: 6, 17.1\]。手先が 2 cm 乖離するだけで衝突率が 13.9% から 31.9% へ跳ね上がる事実が示す通り、負例の引き算ではなく、未踏領域を埋める幾何学的に正しく安全なデモンストレーションの能動的な「再生成」が不可欠である \[cite: 6, 17.1\]。

第二の構造的課題は、合成軌道における「行動空間の飽和と確率分布の歪み」である。時間反転軌道の接近区間において、目標姿勢誤差に基づく比例制御（P制御）と値クリッピング（np.clip や方向を保つスケーリング）を適用した場合、外れ値自体は抑制されるものの、クリップ境界（例：回転指令 $\\pm 0.375$）に全ステップの 28.81% が集中するインパルス状の分布偏重が生じる。微分不可能な境界値に教師信号が過剰蓄積すると、$\\pi\_{0.5}$ などのディープニューラルネットワーク学習時に勾配ノルム（grdn）が 1.4 から 7.8 へと高止まりし、最適化が不安定化する \[cite: 5, 7, 4.4.3\]。その結果、推論時に対象物の手前約 59 mm でアームが停止し、把持動作へ移行できなくなる致命的な制御破綻へと直結する。  
したがって、本課題を根本的に解決するためには、動画や物理状態の再生を通じて問題区間を特定し、人間が直感的かつ局所的に介入・編集できる対話型ツールチェーン、加速度や躍度（Jerk）の連続性を担保し速度制限境界への張り付きを生じさせない時間パラメータ化技術、そして単一または少数の成功デモから環境のばらつきに対応した大規模な軌道を破綻なく自動合成するデモンストレーション拡張パイプラインの導入が必要となる。

## **対話的アノテーションと人間介入型軌道編集システム**

問題のある軌道を効率的に修正する確実なアプローチの一つは、時系列データや描画動画から問題箇所（非意図的な接触、接近時の手首の特異姿勢、物体の滑り・落下など）を特定し、該当区間のみを上書き・再アノテーションするヒューマン・イン・ザ・ループ（Human-in-the-Loop: HITL）型のワークフローである。

### **LeRobot Dataset Visualizer と Rerun.io によるマルチモーダル検査**

近代的なロボット学習エコシステムにおいて、Hugging Face の LeRobot をはじめとする最新フレームワークでは、マルチモーダル時系列データの可視化バックエンドとして Rerun.io の採用が事実上の標準となっている。  
LeRobot Dataset Visualizer は、Next.js、React、Three.js を基盤とした Web アプリケーションであり、動画ストリーム、ロボットの関節角度やエンドエフェクタ姿勢（URDF 3D 描画）、および制御指令（Action）の時系列プロットをミリ秒単位で完全同期させて再生・検証できる。FastAPI バックエンド（NEXT\_PUBLIC\_ANNOTATE\_BACKEND\_URL）と連動させることで、ブラウザ上でエピソードの特定フレームにサブタスク境界、言語指示のタイミング、無効区間フラグなどのアノテーションを付与し、直接 Parquet ファイルへ書き戻す運用が可能である。  
また、スタンドアロンの rerun-sdk（Python / Rust）は、MuJoCo や Isaac Lab などの物理シミュレータ内部から、3D バウンディングボックス、メッシュ、接触力ベクトル、計画軌道をリアルタイムにストリーミングできる。これにより、「どの時刻に対象外物体と接触したか」「どの時刻からエンドエフェクタ速度が飽和しているか」を視覚的かつ定量的に特定し、不要な区間のトリミングや、特定タイムステップからのシミュレータ状態ロールバック（State Rewind）を迅速に遂行できる。

### **ヒューマン・イン・ザ・ループ遠隔操作と共有自律性**

動画を確認して問題箇所を手動で完全に作り直す作業は、全行程を人間が遠隔操作（Teleoperation）すると多大な労力を要するため、自律計画系と人間の介入を組み合わせるハイブリッド手法が研究されている。  
スタンフォード大学と NVIDIA が提案した HITL-TAMP（Human-in-the-Loop Task and Motion Planning）は、障害物のない自由空間移動などの定型区間をタスク＆モーションプランニング（TAMP）に任せ、接触を伴う高難度な作業（把持、嵌め合わせ、設置）でのみ人間に制御権を委譲するアーキテクチャである。TAMP が事前条件や幾何学的制約を検証し、実行不能や把持失敗を検知した瞬間に人間のオペレータへ介入プロンプトを発行する。人間は遠隔操作デバイスを通じて修正動作を入力し、その区間のみがデモンストレーションとして蓄積されるため、従来の全遠隔操作と比較して同一時間内で 3 倍以上の高品質データを収集できる。  
カリフォルニア大学バークレー校の HIL-SERL（Human-in-the-Loop Sample-Efficient Robotic Reinforcement Learning）や HG-DAgger などの介入型フレームワークでは、学習済み方策がタスクを実行している最中に人間が介入ボタンを押して軌道を修正する。介入中の行動履歴は回復行動（Recovery Demonstrations）として優先的にバッファへ蓄積され、方策が苦手とするエラー回復挙動を集中的に教示することが可能である。

### **MOMO と KMP を用いた Web GUI 経由の対話的 Waypoint 編集**

ドイツ航空宇宙センター（DLR）の研究チームが開発した MOMO（Motion Modulation）フレームワークでは、記録された軌道に対して Web インターフェース上で経由点（Via-point / Waypoint）をマウス操作によってドラッグ＆ドロップし、局所的に軌道をモーフィング（変形）させるシステムが実現されている。  
MOMO では、軌道を確率的な動作プリミティブである Kernelized Movement Primitives（KMP）として符号化する。Vue.js ベースの Web 画面上で、利用者が衝突の発生しているフレームに新たな経由点を追加・移動させると、KMP のカーネル回帰により、始点と終点の連続性を保ったまま指定された経由点を通過する滑らかな軌道が瞬時に再計算される。動画上で「皿の縁に当たっている」「棚の天板に近すぎる」箇所を発見した際、該当空間座標のマーカーを上方に数センチ引き上げるだけで、衝突のない安全な軌道へと数秒で書き換えることができる。

## **幾何学的動作計画と動力学制約に基づく時間パラメータ化**

手作業での修正を排し、幾何学的経路から滑らかで物理的に実行可能な制御指令列（Action Sequence）を自動再生成するためには、ロボット工学で確立された「幾何学的パス生成」と「時間パラメータ化（Time Parameterization）」の分離アプローチが最も堅牢である。

### **TOPP-RA（到達可能性解析に基づく時間最適パスパラメータ化）**

時間反転や Waypoint 補間によって幾何学的な空間経路 $p(s)$（$s \\in \[0, s\_{\\text{end}}\]$ はパスの進行度）が定義されている場合、各関節やエンドエフェクタの速度制約・加速度制約を厳密に守りながら最短時間で走破する時間割当 $s(t)$ を決定するアルゴリズムとして、TOPP-RA（Time-Optimal Path Parameterization by Reachability Analysis）が広く利用されている。  
従来の数値積分（Numerical Integration）手法は特異点や制約境界で数値的不安定性に陥りやすく、凸最適化（Convex Optimization）手法は計算負荷が高いという欠点が存在した。TOPP-RA は、パスをグリッド分割し、各グリッド点における二乗速度 $x\_i \= \\dot{s}\_i^2$ の到達可能集合（Reachable Set）および制御可能集合（Controllable Set）を、終端から逆方向パス（Backward Pass）と順方向パス（Forward Pass）の 2 回の走査により、小さな線形計画法（Linear Programming: LP）の連続として再帰的に解く。  
$$x\_{i+1} \= x\_i \+ 2 \\Delta\_i u\_i$$  
$$a(s\_i) u\_i \+ b(s\_i) x\_i \+ c(s\_i) \\in \\mathcal{C}\_i$$  
ここで $u\_i \= \\ddot{s}\_i$ はパス加速度である。TOPP-RA は Python ライブラリ（toppra）として提供されており、数ミリ秒から数十ミリ秒で 100% の成功率をもって解を出力する。制約条件として、各軸の最大速度 $v\_{\\max}$、最大加速度 $a\_{\\max}$ のみならず、所要時間の上限や目標時間（Duration Constraint）を明示的に指定して再時間スケジューリング（Retime）することも可能である。

### **Ruckig（Type V 実時間ジャーク制約軌道生成）**

パスが事前に稠密な Waypoint として存在しない場合や、現在の任意の状態（位置 $p\_0$、速度 $v\_0$、加速度 $a\_0$）から目標状態（位置 $p\_1$、速度 $v\_1$、加速度 $a\_1$）へと滑らかに遷移させたい場合、オープンソースライブラリ Ruckig が強力な選択肢となる。  
Ruckig は、速度限界 $v\_{\\max}$、加速度限界 $a\_{\\max}$ に加え、加加速度（Jerk: 躍度）限界 $j\_{\\max}$ を考慮した 3 次制約（Type V）の時間最適軌道を解析的に導出する。従来の台形速度プロファイル（一定加速度制御）では加速度が不連続にステップ変化するため、微分値であるジャークが無限大となり、シミュレータの内部数値積分や実機の関節トルク制御系において振動や目標追従遅れを引き起こす。Ruckig はジャークを一定値の範囲内に収める S 字速度プロファイル（7-segment profile）を生成し、多自由度の全軸が完全に時間同期して同時に目標状態に達することを保証する。  
C++ コアで実装され Python バインディング（pip install ruckig）を備えており、1 回の軌道計算時間はマイクロ秒オーダーであるため、制御周期 20 Hz 〜 1 kHz のループ内で外乱に応じた動的再計算（Online Replanning）を破綻なく実行できる。MoveIt 2 の標準スムーザーとしても統合されている。

### **5次多項式最小ジャーク軌道（Minimum Jerk Trajectory）**

閉形式で外部依存関係を持たずに実装可能なアプローチとして、5 次多項式（Quintic Spline）による最小ジャーク軌道生成がある。始点 $t=0$ および終点 $t=T$ において、位置が $0 \\to 1$、速度が $0 \\to 0$、加速度が $0 \\to 0$ となる境界条件を解くと、時間進行度 $s \= t/T \\in \[0, 1\]$ に対する重み関数 $w(s)$ は一意に定まる。  
$$w(s) \= 10s^3 \- 15s^4 \+ 6s^5$$  
$$\\dot{w}(s) \= \\frac{1}{T} (30s^2 \- 60s^3 \+ 30s^4)$$  
このプロファイルの最大速度は中間点 $s=0.5$ において発生し、平均速度の正確に $1.875$ 倍（$= 15/8$）となる。台形速度プロファイルのように一定速度で巡航する区間が存在しないため、速度指令ヒストグラムを作成した際に単一の速度値にスパイク状のピークが発生することが原理的にない。  
指令値が配布データの許容エンベロープ（例：並進 0.85、回転 0.30）を超えないように必要ステップ数 $N$ を以下の式で事前に割り振ることで、行動飽和（Action Saturation）を構造的に排除できる。  
$$N\_{\\text{pos}} \= \\left\\lceil 1.875 \\cdot \\frac{L}{u\_{\\max,\\text{pos}} \\cdot K\_{\\text{pos}}} \\right\\rceil, \\quad N\_{\\text{rot}} \= \\left\\lceil 1.875 \\cdot \\frac{\\theta}{u\_{\\max,\\text{rot}} \\cdot K\_{\\text{rot}}} \\right\\rceil$$  
$$N \= \\max(N\_{\\text{pos}}, N\_{\\text{rot}}, N\_{\\min})$$  
ここで $L$ は並進距離、$\\theta$ は姿勢回転角、$K$ は 1 ステップあたりの指令に対する制御器の実移動量係数である。

## **デモンストレーション自動拡張・再合成フレームワーク**

少数の成功デモ（シード軌道）から、環境の配置変動やロボットの初期姿勢変動を網羅する数千〜数万本の新しい軌道を合成するアプローチとして、スタンフォード大学および NVIDIA を中心にデモ生成アーキテクチャが発展している。

### **MimicGen のサブタスク分解と座標系変換**

MimicGen（Mandlekar et al., CoRL 2023）は、少数の人間デモンストレーションを「物体中心（Object-Centric）のサブタスク」に分解し、環境内の物体配置の変化に合わせて幾何学的に変換・再結合（Stitch）することで、数千倍規模のデータを自動生成するシステムである。  
MimicGen の基盤原理は、タスクを「接近」「把持」「移送」「設置」などのフェーズに分割し、把持や設置などの接触密（Contact-rich）な区間の軌道を、ワールド座標系ではなく対象物体のローカル座標系における相対姿勢軌道 $\\tau\_{\\text{obj}}$ として記述することにある。新たな初期配置において対象物体の姿勢 $T\_{\\text{obj}}^{\\text{new}}$ が与えられたとき、相対軌道を適用してエンドエフェクタの目標軌道 $T\_{\\text{eef}}^{\\text{new}}(t) \= T\_{\\text{obj}}^{\\text{new}} \\cdot \\tau\_{\\text{obj}}(t)$ を算出する。各サブタスクの接続部においては、前のサブタスクの終了姿勢から次のサブタスクの開始姿勢への移動を補間または動作計画によって滑らかに接続する。

### **SkillGen（Isaac Lab 2.3）と cuRobo による無衝突合成**

MimicGen は自由空間での接続移動を単純な線形補間や静止座標変換に依存していたため、シーン内に障害物が存在する場合や初期姿勢が大きく離れている場合に衝突が発生しやすい課題を抱えていた。  
NVIDIA Isaac Lab 2.3 で公式統合された SkillGen（SkillMimicGen）は、GPU 加速動作計画ライブラリ cuRobo をパイプラインに組み込むことでこの問題を解決している。SkillGen はタスクを「接触スキル区間」と「自由空間移動区間」に明確に分離する。接触スキル区間は元デモの物体相対動作を厳密にリプレイ・変換する一方で、接近区間や後退区間などの自由空間遷移は、cuRobo の GPU 並列軌道最適化によってリアルタイムに衝突を回避するパスを計画する。  
さらに、物体を把持した瞬間にシミュレータ上で把持物体をロボットのキネマティクスツリーに動的アタッチ（Dynamic Attachment）し、衝突判定用球体（Collision Spheres）を即座に再構成することで、運搬中の障害物との二次衝突を回避した合成軌道を生成できる。

### **CP-Gen（幾何拘束保存型データ生成）**

CoRL 2025 で発表された CP-Gen（Constraint-Preserving Data Generation）は、単一のデモンストレーションから、物体の位置姿勢の変化のみならず「物体の形状・ジオメトリの変化」に対しても有効な軌道を生成する技術である。CP-Gen はスキルをキーポイント軌道制約として定式化し、ロボットまたは把持物体上のキーポイントが、対象物体の表面に対して一定の幾何学的関係を追従するように逆運動学（IK）および軌道最適化を解く。これにより、サイズや形状が異なるカップやボウルに対しても、接触破綻のないデモンストレーションを自動合成することが可能となる。

## **物理シミュレータ統合型モデル予測制御（MPC）**

軌道の幾何学的変換だけでは対処が困難な「滑りやすい物体の把持」「接触を伴う押し動作（Non-prehensile Manipulation）」などの物理的にデリケートなタスクでは、物理シミュレータ自身を予測モデルとして利用するサンプリング型モデル予測制御（Sampling-based MPC）が有効な再生成手段となる \[cite: 4, 10.1, 91, 101\]。

### **MuJoCo MPC（MJPC）と Predictive Sampling**

Google DeepMind が公開した MuJoCo MPC (MJPC) は、MuJoCo 物理エンジン上で直接動作する実時間モデル予測制御フレームワークである。MJPC には、導関数ベースの最適化手法（iLQG、Gradient Descent）に加えて、ガウス分布からノイズを加えた複数の制御入力シーケンスを並行ロールアウトし、最小コストのシーケンスを選択・更新する導関数不要の Predictive Sampling、ならびに MPPI（Model Predictive Path Integral）や CEM（Cross-Entropy Method）が実装されている。  
MJPC は対話型のグラフィカルユーザーインターフェース（GUI）を備えており、タスクのコスト関数（目標位置との距離、他物体との接触ペナルティ、制御入力の滑らかさ）の重みを GUI 上でリアルタイムにスライダー調整しながら、ロボットが自動的に障害物を避けて目標を把持・運搬する挙動をプレビューおよび記録できる。

### **Judo と Hydrax による GPU 並列加速**

従来の CPU ベースの MPPI では、1 つの軌道を最適化するために数万回のシミュレーションステップを要し、1 軌道の生成に 50 分以上を費やすことが実用上の障害となっていた \[cite: 4, 10.1\]。この計算コストを劇的に低減するために登場したのが、JAX および MuJoCo X（MJX）を活用した GPU 並列 MPC ライブラリである。  
Hydrax は GPU 上で数百から数千の制御候補を完全並列にロールアウトし、ミリ秒単位で MPPI や Predictive Sampling の解を収束させる。また、ボストン・ダイナミクス AI 研究所（BDAI）が開発した Judo は、Python による簡潔なインターフェースと MuJoCo マルチスレッド C バックエンドを統合し、タスクのインタラクティブなパラメータチューニングと高速軌道最適化を両立している。既存の粗いデモ軌道を初期ノミナル入力として与え、その周囲に微小なガウス摂動を与えて並列ロールアウトし、「対象外物体との距離」を負のコストとして課すことで、元の動作意図を保持したまま接触のないクリーンな軌道へと短時間で修復できる \[cite: 6, 10.1, 101, 103\]。

## **拡散モデルに基づく軌道インペインティングと階層生成**

模倣学習において、画像生成で成功を収めた拡散モデル（Diffusion Models）を軌道全体の計画器として利用する Motion Planning Diffusion（MPD）や Trajectory Inpainting 技術も進展している。

### **拡散モデルによる軌道インペインティングの数理**

拡散確率モデル（DDPM）において、軌道全体を $\\tau \= \[x\_0, x\_1, \\dots, x\_T\] \\in \\mathbb{R}^{T \\times D}$ とする。Trajectory Inpainting では、軌道の一部（既知の初期姿勢 $x\_0$、把持姿勢 $x\_T$、あるいは正常な中間区間）を観測マスク $M \\in \\{0, 1\\}^{T \\times D}$ によって固定し、未定義または問題のある破損区間 $(1 \- M) \\odot \\tau$ のみを逆拡散過程において条件付き補完（Inpainting）する。  
各ノイズ除去ステップ $k$ において、既知領域は前方拡散過程に従って加えたノイズ状態 $x\_t^{(k)} \\sim q(x\_t^{(k)} \\vert{} x\_t^{(0)})$ で置き換えられ、未知領域のみがデノイジングネットワーク $\\epsilon\_\\theta$ によって推定される。  
$$\\tau^{(k-1)} \\leftarrow M \\odot \\tau\_{\\text{known}}^{(k-1)} \+ (1 \- M) \\odot \\tau\_{\\text{sampled}}^{(k-1)}$$  
このメカニズムにより、時間反転によって得られた運搬・設置区間と、新環境の初期姿勢との間を、過去の多様な動作データセットの事前分布（Prior）に合致し、かつ障害物との幾何的干渉を起こさない自然な軌道で自動的に縫い合わせる（Stitching）ことが可能になる。

### **階層的拡散モデルと運動学蒸留（HDP / RK-Diffuser）**

純粋な Cartesian エンドエフェクタ空間で拡散モデルを適用すると、逆運動学（IK）の特異点や関節可動域制限に抵触するリスクがある。階層的拡散方策（Hierarchical Diffusion Policy: HDP）および RK-Diffuser は、上位エージェントが視覚特徴と言語指示から遠方の Next-Best-Pose（NBP）を予測し、下位の RK-Diffuser が微分可能運動学（Differentiable Kinematics）制約のもとで関節角度空間の連続軌道をインペインティングする。関節空間の平滑性とエンドエフェクタの幾何学的追従性が同時に最適化されるため、急峻な関節角速度変化や特異姿勢での停止が排除された高品質なデータが生成される。

### **フェーズ1（即時対応）：アプローチ区間の速度プロファイル置換**

現在 replay\_video\_probe.py で行われている比例制御と値クリッピング（osc\_command の np.clip）を直ちに廃止し、解析的な最小ジャーク軌道生成または Ruckig による時間パラメータ化へ移行する。  
現在のエンドエフェクタ姿勢から目標把持姿勢（transfer または top-down）までのユークリッド距離 $L$ および四元数回転角 $\\theta$ を計算し、配布データの最大許容エンベロープ（並進指令 $u\_{\\text{trans}} \\le 0.85$、回転指令 $u\_{\\text{rot}} \\le 0.30$）と 1 ステップあたりの実移動量係数 $K\_{\\text{pos}}, K\_{\\text{rot}}$ を用いて、飽和を起こさない最小必要ステップ数 $N$ を算出する。ステップ $i \= 1, \\dots, N$ において、5 次多項式重み $w(i/N) \= 10(i/N)^3 \- 15(i/N)^4 \+ 6(i/N)^5$ により、並進位置は線形補間、姿勢は球面線形補間（SLERP）した目標姿勢シーケンスを生成する。  
move\_to ループ内では、生成された中間 Waypoint を 1 ステップごとに制御器（OSC）の目標値として与える。事後的なクリッピングに頼らないため、指令値の絶対値は常に滑らかな曲線を描き、境界値への張り付き（$\\vert{}z\\vert{} \> 10$ や $\\pm 0.375$ のインパルス集中）が理論上完全に解消され、勾配の健全化と推論時の手前停止問題が解決される。

### 

### **フェーズ2（短期対応）：Rerun による異常検知と Waypoint 微修正**

生成された反転軌道および合成デモの品質検証を自動化・対話化する。  
書き出された Parquet または NPZ ファイルから、rerun-sdk を用いてロボット手先座標、対象物座標、および対象外物体の変位量をタイムライン付きでストリーミングするビューワーを配備する。シミュレータ内部の接触判定（contacting\_bodies）および物体の $z$ 軸変位を監視し、対象外物体が 1 mm 以上動いたエピソードや、把持解除後に物体が落下したエピソードを自動検出してフラグを付与する。  
問題が局所的な接触である場合、把持直後の上昇量（LIFT）を 80 mm から 100 mm へ引き上げる調整や、設置直前の下降速度を抑えるパラメータを適用してシミュレーションを再実行（Re-rollout）し、クリーンな軌道のみをデータセットに組み戻す。

### 

### **フェーズ3（中期対応）：SkillGen パターンに基づく系統的データ増強**

Track 2 で露呈した「初期姿勢のばらつきに対する脆弱性」を抜本的に解決するため、正例デモンストレーションの系統的増強を実施する \[cite: 6, 17.1\]。  
既存の成功デモを「接近」「把持」「運搬」「設置」の 4 フェーズに自動アノテーションし、ロボットの初期関節位置やベース位置をランダムに $\\pm 2 \\sim 5\\text{ cm}$ 摂動させた環境を構築する \[cite: 6, 17.1, 151\]。初期姿勢から把持前待機点（Standoff Pose）までの接近軌道を、単なる固定動作のリプレイではなく、TOPP-RA や幾何学的衝突フリーパス探索によって動的に生成する。物体を把持して運搬・設置する接触密な区間は、把持対象物体のローカル座標系に投影されたオリジナルの高精度な相対動作をそのまま再生する。  
これにより、把持の滑りや非意図的な接触を完全に回避したまま、多様な初期姿勢からタスクを完遂する頑健なデモンストレーション数千本を自動再合成することが可能となり、方策の評価スコアを大幅に向上させることができる \[cite: 6, 17.3, 17.4, 34, 151\]。
