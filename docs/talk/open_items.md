### 4. ロールアウトの動画 — **撮れるようにした。次の評価で撮れる**

**なぜ要るか。** 本番の 8 本中 4 本が、2 回とも 300 歩を使い切って
ゴールに届いていない。**止まっているのか、往復しているのか、掴めずに
空振りしているのか——成功率と衝突率では区別できない。**

**採点ハーネス側に入れた。** [rollout_recorder.py](../../solution/tools/rollout_recorder.py) が本体で、
[patch_kit_for_variants.py](../../solution/tools/patch_kit_for_variants.py) が
キットの `pipeline/rollout.py` へ差し込む。**提出物には一切手を入れていない。**

> **提出物側に入れても意味が無い。** 採点環境が返すのは標準出力のログだけで、
> ファイルは 1 つも戻ってこない（`docs/prod_eval_results/` の 3 件はすべて
> ログ本文である）。**本番のあの 4 本そのものは撮れない。** 撮れるのは
> 手元と Colab の回で、そこにも打ち切りに張り付いた回は
> **80 本中 13 本**ある（8/10 の測定）。

**回し方。** GPU マシンなら**既定で有効**なので、3 を流せば撮れる
（[03_gpu_eval.md](../howto/03_gpu_eval.md)）。手元の Docker で試すときは
環境変数を 1 つ渡す。

```bash
PARC_RECORD_DIR=/out/videos bash solution/tools/run_local_eval.sh
```

| 変数 | 既定 | 意味 |
|---|---|---|
| `PARC_RECORD_DIR` | （空） | 出力先。**空なら完全に無効** |
| `PARC_RECORD_WHICH` | `failures` | **既定で失敗した回だけ残す。** `all` で全部 |
| `PARC_RECORD_MAX` | `40` | 本数の上限。ディスクの保険 |

**84 件を全部見る必要は無い。** 既定が `failures` なので、成功した回は
書き出さない。撮れたものは分類して並べる。

```bash
python3 solution/tools/summarize_rollout_videos.py work/smoke/videos
```

**打ち切りに張り付いた回が先頭に来て**、1 本ずつ 8 コマの静止画になる。
動画を再生する前に、まず静止画で当たりを付けられる。

**測った費用**（手元で実測）。90 分の測定に相乗りさせて構わない。

| 測ったもの | 値 |
|---|---|
| 1 歩の上乗せ | **0.33 ms**（本番の `env.step` 39 ms に対して 0.8%） |
| メモリの山 | 31 MB（300 歩・2 カメラ） |
| 84 件を全部撮った場合 | 90 分に **+2.9 分** |

**検査したこと。** 前任の [visualize_actions.py](../../solution/tools/visualize_actions.py) は
一度も走らせずに置かれていたので、同じことを繰り返さないようにした。

| 確かめたこと | 結果 |
|---|---|
| mp4 が本当に再生できるか（読み返してコマ数を数えた） | **4 本すべて OK**（40/60/30/25 コマ、768×384） |
| 映像の向きがモデルへ渡るものと一致するか | `LiberoProcessorStep` の `flip(2,3)` と**画素単位で一致** |
| 焼いた文字が読めるか | **読めた**（`1/40 grip CLOSE` / `path 0.00m disp 0.00m` / `stalled` / `TIMEOUT`） |
| 「静止」と「往復」を撮り分けられるか | **5 通りで確認**（下） |
| 既定（`failures`）で成功が撮られないこと | **撮られない。** 未完了と衝突だけが残る |
| `PARC_RECORD_MAX` の上限が効くこと | **効く。** 5 本目は撮らなかった |
| コマ並べ画像が出ること | **4 枚。** 未完了が先頭に来る |
| 録画が壊れても評価が続くか | **続く。** 1 度だけ警告を出して以降は諦める |
| 何度パッチを当てても壊れないか | 冪等（2 度目は「適用済み」） |

**動きの判定は 5 通りで確かめた**（`cv2 4.11.0`、キットの固定と同じ版）。

| ケース | 経路長 / 変位 | 焼かれたラベル |
|---|---|---|
| 震えだけ | 0.00m / 0.00m | `stalled` |
| 小さく往復 | 0.32m / 0.02m | `wandering` |
| 大きく往復 | 2.37m / 0.03m | `wandering` |
| まっすぐ進む | 0.29m / 0.29m | （なし） |
| 進んで少し戻る | 0.30m / 0.24m | （なし） |

> **2 件直した。どちらも動かして初めて分かった。**
>
> **① 判定の閾値が緩すぎた。** 「変位が小さく、経路長が 0.5 m 超」を往復と
> していたので、**60 歩で 0.32 m 行き来した回を「静止」と呼んでいた。**
> 下限を 0.10 m へ下げ、さらに**経路長が変位の 8 倍を超える**条件を足した
> （2.37 m / 0.03 m の回が絶対値の網だけでは漏れた）。
> **停滞の検知（項目 9）はこのラベルを見て設計するので、ここを誤ると打つ手を間違える。**
>
> **② 日本語が映像で化ける。** キットが固定している opencv 4.11 の `putText` は
> 日本語を `?` にする（「衝突」→「??????」）。映像に焼く文字は
> `COLLIDED` / `TIMEOUT` の ASCII にし、日本語はファイル名とログに残した。

**まだやっていないのは、本物の LIBERO-plus に対して回すことだけである。**
録画の配線だけを数分で確かめるなら、重みを使わずに済む。

```bash
RECORD=1 bash solution/tools/smoke_test_suite.sh   # 5 タスク・20 歩
```
