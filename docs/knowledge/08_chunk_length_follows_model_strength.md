# 08. chunk 長の最適値は、モデルが強くなるほど大きくなった

**同じ探索を 2 つのモデルで行い、最適値が n=2 から n=16 へ動いた。**
講義資料が述べる一般則とも噛み合う。

## 何を変えているか

`n_action_steps` は、**1 回の推論で作った行動列のうち、何ステップぶんを実行してから
作り直すか**である。大きいほど作り直しの回数が減る —— つまり、新しい観測を見ずに動き続ける時間が長くなる（オープンループ）。

**chunk は常に 50 ステップぶん作られる。**実行するのはその先頭 n ステップだけで、残りは捨てる。

## 読み

| モデル | 最適な n |
|---|---|
| SmolVLA（0.4B・弱い） | **2〜5** |
| **π0.5（4.14B・強い）** | **16** |

**講義資料（`docs/materials/第7回 講義資料part1.pdf` p.10）が機構を説明している。**

> 「k が短すぎる（k=2）／チャンク境界のたびに分布から別のモードをサンプルしうる
> → mode-jumping・jerky（ガクガク）な動き」。一般には **k=16〜32 が普通**。

**n=1 の悪化はこれで説明できる**——1 ステップごとに境界が来るので、そのたびに別のモードを引く。

**弱いモデルで n=2 が最良だったのは、誤差の蓄積を頻繁に打ち切る必要があったため**
と読める。**モデルが強くなれば誤差が溜まりにくいので、長くオープンループで流せる。**

## 実務上の意味

**モデルを載せ替えたら、chunk 長は必ず測り直す。**
前のモデルの最適値をそのまま使うと、大きく損をする。

- SmolVLA の最良値 n=2 を π0.5 にそのまま当てていたら、n=16 の 0.264 を逃していた
- π0.5 の既定値は 10 で、**16 に上げるだけで本番 0.177 → 0.264（+0.087）**だった

**上げすぎも駄目である。**π0.5 の n=32 は手元で成功率が 0.694 → 0.583 に落ち、
**36 件中 13 件が 300 ステップの上限に達した。**山があり、頂上は探さないと分からない。

## ステップ数との関係

**最適な n は、ステップ数が最小になる n でもあった。**

| n | ステップ数 | スコア |
|---|---|---|
| 10 | 1,428 | 0.177 |
| **16** | **1,142** | **0.264** |

## Claude 側 / 人間側

**Claude 側**: **モデルを載せ替えたとき、前のモデルで決めた設定値を引き継がない。**
「前は n=2 が最良だった」は新しいモデルについて何も言っていない。
**引き継いだ値には「このモデルでは未測定」と明記して報告する。**

**人間側**: **配布された既定値も「誰かが別の条件で決めた値」である。**
π0.5 の既定は 10 だったが、最適は 16 だった。**既定値は測り直す候補の筆頭。**

**両方**: **山がある設定値は、両側を測って初めて頂上と言える。**
n=16 が最良だと言えるのは、10 と 32 の両方を測ったからである。
片側しか測らずに「上げるほど良い」と外挿すると、n=32 の崖に落ちる。
