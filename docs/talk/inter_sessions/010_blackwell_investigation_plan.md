## 何をしてほしいか

**明日（8/30）の午後〜夕方〜夜に、ユーザが順に打っていけるだけの調査計画を作ってほしい。**

成果物は **1 つのファイル**である——`docs/howto/14_blackwell_first_session.md` を
**書き足して現状に合わせるか、それでは収まらないなら `docs/howto/` に節を足す。**
**新しい計画文書を別に作らないこと**（同じことが 2 か所に書かれると必ず片方が古くなる）。

**計画に入れてほしいもの。**

1. **時間割。**「午後」「夕方」「夜」の 3 つに割り、**それぞれ何分で何をするか。**
   **夜は放置できるものを置く**（ユーザは在席しない）。
2. **調査項目の一覧。**下の「前提となる事実」に挙げたものは種であって、
   **項目の洗い出しそのものを任せたい。**
3. **打つコマンド。**省略せずそのまま貼れる形で。
4. **判断が要る場所と、その場での決め方。**「VRAM が 96 GB でなかったら batch をいくつにするか」
   のように、**分岐を先に書いておく。**

## なぜ要るか

**Blackwell は無料の機械で、いま唯一空いている。**しかし
**ユーザが在席できるのは明日の午後〜夕方だけで、その間に「使えるかどうか」を確定させたい。**
**使えると分かれば、対照の学習を無料で回せる。**使えないと分かれば、
**RunPod に $50 を積む判断をその日のうちにできる。**
**どちらに転んでも、その日の終わりに次の 1 手が決まる。**

## 前提となる事実（項目の種。**足りないものを足してほしい**）

### 機械について確かめること

| 何を | なぜ要るか |
|---|---|
| **VRAM の実測** | batch 64 で 49.37 GB 使う。96 GB なら余裕があるが、共有だと分からない |
| **CPU の数** | `--num-workers` を決める（いまは `nproc` の半分か 16 の小さいほう）。**評価をここで回すなら描画の速さがこれで決まる** |
| **ディスクの空き** | チェックポイント 1 個 25 GB（うち `pretrained_model` 8.8 GB）。**データセットも展開する** |
| **`pip install` が通るか・外へ出られるか** | **HF から重み 8.8 GB を落とせるかが分かれ目である。**落とせないなら別の運び方を考える |
| **torch と CUDA の版** | Blackwell 世代は新しい版を要ることがある |
| **セッションの寿命** | Notebook が切れると学習も死ぬ。`tmux` や `nohup` が使えるか |
| **`egl` が使えるか** | 評価をここで回せるかが決まる（`osmesa` だと CPU 律速） |

### 配布データセットについて確かめること（**ここを厚くしてほしい**）

**種として 4 つ挙げる。これ以外も洗い出してほしい。**

1. **配布されているのは何と何か。**上の 6 つと一致するか。
   **`libero_combined_20hz`（統合 20Hz）が別にあると聞いている**——それは何の統合か。
2. **相互の重複。**`libero_plus` の 40 タスクは、`libero_90` の 73・`libero_10` の 10 と
   どれだけ重なるか。**LeRobot 形式なら `meta/tasks.jsonl` にタスク名がある**ので、
   展開せずに名前の集合を突き合わせられる。
3. **トラックごとにどれを使うべきか。**
   - **Track3 の元タスクは SCENE 名**（`libero_90` に 90・`libero_10` に 30）。
     **`libero_plus` に SCENE 名のタスクが入っているかを数えると、
     Track3 に向けて何を足すべきかが決まる。**
   - Track1・Track2 は摂動（背景・照明・視点・姿勢）が要るので `libero_plus` が中心になるが、
     **`libero_90` の 73 タスクを足すとタスクの幅が広がる。**
4. **`no_noops` と素の版の違いが、こちらの学習にどう効くか。**
   いま使っている `libero_plus` は `no_noops` 相当か。

### 分かっている落とし穴

| 落とし穴 | 対処 |
|---|---|
| **`docker` は使えない** | Notebook へ直に pip。**採点環境は Python 3.10 固定** |
| **`hf auth login` を忘れると非公開リポジトリが `not found` に見える** | 先にログイン。「無い」と言われても名前の間違いではない |
| **学習のチェックポイントに `vlm/` は付かない** | 評価も zip も落ちる。`001500` から `cp -r` する（`ln -s` は駄目） |
| **`df` が答えない共有ストレージがある**（RunPod の Network Volume で踏んだ） | 使用量は `du`、枠は管理画面 |
| **ディスクが埋まると書いている途中のファイルが壊れる** | 書く前に空きを見る。`write_text` は truncate してから書く |

## 判断が必要になったら

**この依頼の目的は「明日の夜の終わりに、Blackwell を実験に使えるかどうかを確定させ、
使えるなら何を回すかまで決まっている」ことである。**

**その目的に照らして、順番や項目を変えてよい。**
たとえば**外へ出られるかどうかは最初に確かめるべきである**——
それが駄目なら重みを運べず、学習の話が全部消えるからである。
**同じ理由で、確かめる順は「安いものから」ではなく「これが駄目なら全部消えるものから」にする。**
**変えた場合は理由を報告に書くこと。**

**次の 2 つは範囲の外にしてほしい。**

| 範囲の外 | なぜ |
|---|---|
| **提出物を Blackwell で組むこと** | zip は 9.4 GB で、運ぶだけで時間を食う。**組むのは重みがある機械で行う** |
| **新しい計画文書を作ること** | `howto/14` と 003 があるので、3 つ目を作ると必ず古いものが残る |
