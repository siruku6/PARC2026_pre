## 環境まわり

### 5. Docker イメージ（CPU 版）を建て直す

```bash
docker build --build-arg TORCH_INDEX=https://download.pytorch.org/whl/cpu \
    -t parc2026-train:cpu solution/train
```

**1 回目（8/10）は 8 段中 6 段目で失敗した。原因を直したので再実行してほしい。**
最後にこう出れば通っている。

```
torch 2.11.0+cpu / torchcodec 0.11.1 整合
```

**何が起きたか。** Dockerfile が torchcodec だけ `--index-url` を付けずに
入れていたため、**PyPI から CUDA 入りの wheel が落ちてきた。**
torchcodec の README いわく「Linux では CUDA 入りが既定で入り、GPU が無くても
動く」だが、それは `libnvrtc` があればの話である。CPU 版の torch には
CUDA ライブラリが 1 つも入っていない。

```
OSError: libnvrtc.so.13: cannot open shared object file
```

**これは CPU 版だけの話ではない。** PyPI の 0.11.1 が要求するのは `.so.13`
（CUDA 13）なので、**既定の cu128（`.so.12` を持ってくる）でも同じ失敗になる。**
本命の GPU 版のための修正でもある。

**検証ステップは正しく働いた。消してはいけない。** LeRobot の自動フォールバックは
`importlib.util.find_spec("torchcodec")` で判定しており、**入ってさえいれば
壊れていても「使える」と答える。** ここで止めなければ、学習データ 6.4 GB を
落としきったあとにデコードで落ちていた。

Mac（Apple Silicon）でも 6 段目まで到達したので、**arm64 の wheel は問題ない。**
`--platform linux/amd64` は要らない。
**ただし学習そのものは Mac では回せない**ので、これは
「Dockerfile と train.py の書き間違いを先に潰す」ためだけの作業である。

## 提出の運用

### 13. 最終提出と同じ zip を、事前にリーダーボードで通しておく

参加者ガイド p.12：

> 予選最終評価にて行われる評価プロセスとリーダーボード評価プロセスの
> **差分は実施される評価タスクのみ**なので、予選最終提出をする前に十分に
> チェックを行うこと。基本的に、**予選最終提出時に生じたエラーに関しての
> 救済措置はありません**

**残りの提出回のうち 1 回は、最終提出と同じ zip の動作確認に充てる。**
学習した重みを載せると zip の中身が変わるので、**この確認は必ず要る。**

> 2 の答え次第で組み立てが変わる。**最後の 1 回が最終提出を兼ねるなら、
> リハーサルはその 1 つ前に置く。**

### 12. 測っていないつまみ

3 が終わってから。どれも 1 回 90 分（検証スイート・`MAX_STEPS=300`）で測れる。

| つまみ | 狙い | 優先度 |
|---|---|---|
| `PARC_BLEND_STEPS=3` | chunk の継ぎ目の段差を消す | 中 |
| `PARC_N_ACTION_STEPS=2` | さらに閉ループ寄りに | 中 |
| `PARC_SAMPLES=3` | 外れた chunk を捨てる。**コストが 3 倍** | 低 |

**`PARC_EMA_ALPHA` は測定済み**（0.3 を既定に採用）。
