ご提示いただいた3つの具体的な課題（**①複数タスクの連結・長尺化**、**②色やテクスチャ・背景の変化**、**③カメラ視点・ロボット/物体位置の移動**）は、LIBERO benchmark やリアル環境におけるVLA（Vision-Language-Action）モデルのボトルネックとして現在最も活発に研究されている領域です。

これらの課題に対する最新の研究成果・現場での応用例を網羅的にサーベイし、それぞれの特徴を比較整理した上で、PARC2026の開発期間（20日周期）および単一L4 GPU（VRAM 24GB）環境で絶大な効果を発揮する**特にお勧めする4つの工夫・アプローチ**を提案します。

## 上位お勧めアプローチ（4選）とその理由

数ある工夫の中でも、**PARC2026のルール制約（単一L4 GPU、推論遅延10秒/ステップ以内、成功率×滑らかさの積算スコア）** に最も適し、かつ20日間のスプリント開発で即座にスコアへ直結する4つのアプローチを厳選しました。

### お勧め1: サブタスク進捗・完了予測（SeqVLA / PALM 方式）の追加

* **アプローチの特徴:**
VLAのアクション予測ヘッド（Action Head）の横に、**「サブタスク完了フラグ（0 or 1）」** または **「進捗スカラー値 $p_t \in [0, 1]$」** を予測する軽量なサブヘッドを追加して共同学習（Multi-Task Learning）させます。
推論時には、モデルが「現在のサブタスク完了（$p_t > 0.95$）」を検出した瞬間に、内部状態をリセットするか次の言語指示文（例: 「Aを掴む」$\rightarrow$「Bに置く」）へ自動でプロンプトを切り替えます。


* **お勧めする理由:**
* **長尺・連結タスクでの壊滅的失敗の防止:** エンドツーエンドのVLAが複数タスク連結（Track 3等）で失敗する最大の原因は、「まだ掴んでいないのに置きに行こうとする（フライング）」や「置いた後もグリップを開かない」といった位相のズレです。進捗値を学習させることで、状態が物理的に完了するまで次の動作へ移行しない粘り強さが生まれます。


* **計算コストがほぼゼロ:** 巨大な視覚言語モデルを追加生成させる Visual CoT 等と異なり、出力層にスカラ値を1つ増やすだけなので、推論遅延やVRAM消費への影響が皆無です。





---

### お勧め2: ReVLA（ビジョンバックボーンのフリーズ/低学習率化）× LIBERO-plus 色・照明 Augmentation

* **アプローチの特徴:**
ファインチューニング（SFT/LoRA）を実施する際、**SigLIPやDINOv2などの視覚エンコーダ（Vision Encoder）の重みを完全にフリーズ（Freeze）** するか、言語・動作層の $\frac{1}{10} \sim \frac{1}{100}$ 以下の極小学習率を適用します（ReVLAの手法）。
これと同時に、学習データとして提供されている `Sylvest/LIBERO-plus` データ（照明・テクスチャ変更版）を使用し、さらにオンラインでランダムカラージッター（Color Jittering）やコントラスト変化の画像拡張を掛けます。


* **お勧めする理由:**
* **視覚表現の破綻（Catastrophic Forgetting）の防止:** 事前学習済みの強力なVLM（Vision-Language Model）は本来、色や背景の変化に強い表現力を持っています。しかし、ロボットの軌道データだけでフルファインチューニングを行うと、視覚バックボーンが特定シーンの背景色に過剰適合してしまい、色やテクスチャが変わった瞬間に動作が崩壊します。


* **Track 1 / Track 2 のスコア激増:** 背景や照明が変化する環境でも、物体（ターゲット）の輪郭や空間位置を正確に捉え続けることができるため、視覚的摂動に対する成功率が飛躍的に向上します。





---

### お勧め3: 手首カメラ（Wrist Camera）の統合 と 相対動作座標（Relative/Local Control）の導入

* **アプローチの特徴:**
モデルへの画像入力として、三人称視点（Agentview）だけでなく、ロボットのアーム先端についている**手首カメラ（Wrist Cam）の画像を必須入力として結合**します（OpenVLA-OFT+等で有効性が実証）。
さらに、モデルが出力するアクションを「ワールド絶対座標での移動量」ではなく、「現在のアーム先端（EEF）の姿勢から見た相対移動量」として定義・学習させます。


* **お勧めする理由:**
* **カメラアングル・ロボット初期姿勢変更（Track 2）への完全解:** 三人称カメラの設置位置や傾きが変わると、絶対座標に頼るモデルは対象物体の方向を見失います。しかし手首カメラはアームと一緒に移動するため、アプローチ直前（把持の瞬間）の局所的な画像変化はカメラ視点がどう変わろうと常に一定です。


* **ミリメートル単位の精密な把持:** カメラのキャリブレーション誤差や位置ノイズが存在しても、手首カメラと相対制御の組み合わせによって、把持位置のズレを自己補正しながら接近できます。





---

### お勧め4: Policy Server 内での明示的・暗黙的エラー検出と「自律リトライ（Failure Recovery）」ルーチン

* **アプローチの特徴:**
`policy_server.py` の制御コード内で、ロボットの状態（アームの関節角・グリッパーの開閉状態・センサ値）を監視します。
例えば「物体を掴むためにグリッパーを閉じたが、指の幅が完全に閉じてしまっている（＝物体を空振りして掴めていない）」という失敗状態を検出した場合、**エピソードを中断せず、アームを5cm上に持ち上げて少し手前に引き、再度アプローチ動作を開始させる非同期ロジック**（またはモデルの内部キャッシュをリセットしてやり直させるロジック）を組み込みます。


* **お勧めする理由:**
* **「失敗率＝0点」を回避する最大の防御策:** PARC2026のスコア評価関数は「成功率（Success Rate）」が全体にかかるゲート（掛け算）として機能します。初期位置や物体のズレによって1回目の把持に失敗しても、時間内（1リクエスト10秒以内 / タスク全体制限時間内）に自律リトライして最終的に成功させれば、完全な失敗（0点）を回避して高スコアを維持できます。


* **追加の学習が不要:** 複雑なポリシーを再学習させなくても、`get_action` メソッド内の状態遷移ロジック（if文やセンサ判定）で実装可能なため、非常に即効性が高い工夫です。

## 次の20日間スプリントにおける具体的な実装アクションプラン

これらの工夫を、現在所有されているベースラインコード（`PARC2026_final` / OpenPI / LeRobot）へ落とし込むための段階的開発手順です。

```
【第1ステップ：1〜5日目】視覚耐性と入力の強化（課題②・③対策）
 1. 学習パイプライン（`examples/pi05_libero_finetune`）において、Vision Encoderの重みをフリーズする設定（ReVLA方式）を適用 [cite: 7, 13, 14]。
 2. データロード時に `Sylvest/LIBERO-plus` を読み込み、手首カメラ（Wrist Cam）画像を観測入力に必ず結合する [cite: 7, 14, 15, 16]。

【第2ステップ：6〜12日目】進捗ヘッドの追加とマルチタスクSFT（課題①対策）
 1. モデルの出力層（Action Head）に、1次元の「Subtask Progress ($p_t$)」を予測する全結合層を追加 [cite: 4, 5]。
 2. データセットのエピソード時間（ステップ数 $t / T$）を進捗正解ラベルとして与え、アクション損失（$L_1$ loss）と進捗損失（MSE loss）を同時にバックプロパゲーションして学習 [cite: 5]。

【第3ステップ：13〜20日目】Policy Serverでの自律リトライ・後処理の統合
 1. `policy_server.py` 内で $p_t > 0.95$ と予測された際、次のサブタスク指示へ自動遷移するロジックを実装 [cite: 1, 5, 6, 7]。
 2. グリッパーの空振り（把持失敗）を判定するロジックと、失敗時にアームを少し戻して再試行させるリカバリ挙動を組み込む [cite: 1, 12, 17]。
 3. 前回提案した EMA / Savitzky-Golay フィルタを通し、滑らかさ（Jerk/SPARC）を保ったまま提出zipを作成してテスト実行 [cite: 6, 7, 18, 19, 20]。

```

以上の「進捗予測（SeqVLA/PALM）」「Vision Encoder フリーズ（ReVLA）」「手首カメラ統合」「自律リトライ（Recovery）」の4点を導入することで、複数タスクの連結・視覚変化・位置ズレのすべてに対して隙のない極めて堅牢な制御システムを構築できます。
