## なぜモカポットを強調に足すのか — **足さないと 45 本のうち 12 本しか使われない**

**`--emphasize-tasks` に入れなかったタスクは間引かれる。** weak3x は得意タスクを
**27% に間引いて**苦手 3 タスクの割合を 3 倍にした（4,609 本 / 13,946 本から逆算）。
**台本 45 本もその 27% を受けるので、`round(45 × 0.27) = 12 本`しか残らない。**

| | 足さない | **足す** |
|---|---|---|
| 使われる台本 | **12 本 / 45 本** | **45 本すべて** |
| コマ数の割合 | 約 0.4% | **約 4%** |

### 他の指示文と比べたモカポットの位置（`solution/tools/demo_lengths.json`）

**手本の長さが 40 タスク中で突出している。**

| タスク | 本数 | 中央 | p90 | 最長 |
|---|---|---|---|---|
| **put both moka pots on the stove** | **146** | **396** | **458** | **505** |
| put the yellow and white mug in the microwave and close it | 160 | 287 | 343 | 449 |
| put both the alphabet soup and the tomato sauce in the basket | 240 | 282 | 340 | 367 |
| turn on the stove and put the moka pot on it | 390 | 265 | 307 | 323 |
| …（36 タスク） | 200〜500 | 89〜264 | 97〜292 | 119〜330 |

**`--max-demo-steps 300` を掛けると、モカポットだけが 146 本すべて落ちる**
（最短 341 歩。[../reference/13_holdout_episodes.md](../reference/13_holdout_episodes.md)）。
**つまり weak3x は 40 タスクのうち 39 タスクしか学んでいない。**

| | 値 |
|---|---|
| データセット全体に占めるモカポット | 2.7%（59,320 コマ） |
| **weak3x の学習に入った分** | **0%** |
| 台本 45 本 | 10,485 コマ |

**残る不安は本数の桁が違うこと**（45 本 対 他タスク 200〜500 本）。倍率を掛けても
**同じ 45 本を 2.6 回見るだけで、種類は増えない。** 台本の動きを丸暗記して、
それが他のタスクへ漏れる恐れがある。**だから C（36 件の副作用）を必ず見る。**

## 次にどのタスクの台本を作るか — **失敗の型で選ぶ**

**モカポットだけが特別である**（300 歩以下の手本が 0 本）。他のタスクには手本があるので、
台本の意味は「もっと良い手本を足す」に変わり、**根拠が 1 段弱くなる。**

**それでも意味がある型が 1 つある。**

| 失敗の型 | 台本の効き |
|---|---|
| **掴もうともせず止まる**（型①） | **効く見込み。**掴む動作の手本が足りない |
| **掴み直しを繰り返す**（型②） | **効く見込み。**その姿勢の手本を台本なら作れる |
| 別の物を掴む | 効かない（言語・視覚の問題） |
| ゴール到達後に衝突 | 効かない（軌道の質） |

**判断の材料は失敗した回の映像である。** コマ並べを作れば再生せずに読める。

```bash
docker run --rm -v "$PWD:/w" -w /w parc2026 \
    python3 solution/tools/summarize_rollout_videos.py <回>/videos
```
