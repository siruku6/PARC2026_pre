# 評価の道具（`solution/tools/eval/`）

**手元の評価は「壊れの検出」に使う道具である。重みの良し悪しの判定には使えない**
——2026-08-29 に、72 行が「効いた証拠なし」と言った重みが採点側で
Track1 0.370 → 0.492 を出した（[knowledge/18](../../../docs/knowledge/18_local_eval_missed_the_gain.md)）。

## 何をしたいときに何を使うか

| したいこと | 使うもの |
|---|---|
| 重みや設定を 1 本まわす | `run_final_eval.sh`（**`docker run` を使うので Claude からは叩けない**） |
| 出た結果に採点式の形の点を付ける | `score_composite.py` |
| **2 つの実行を、タスクを対にして比べる** | **`compare_runs_by_task.py`** |
| 2 つの実行を、物の変位で比べる | `compare_object_disp.py`（`object_disp.jsonl` がある実行どうしだけ） |
| 評価する行（タスク × 条件）の集合を作る | `make_validation_suite.py`・`check_validation_suite.py` |
| variant を評価キットに読ませる | `patch_kit_for_variants.py`・`kit_patches/` |
| 動画を録る | `rollout_recorder.py`（`RECORD=1` で `run_final_eval.sh` から呼ばれる） |

## `compare_runs_by_task.py` —— 率ではなく対で読む

```bash
python3 solution/tools/eval/compare_runs_by_task.py \
    work/final_eval/0828_002049_track2_val72base \
    work/final_eval/0828_224224_track2_trial1500_s1500
```

**引数は実行ディレクトリ 2 つ**（`results/*.json` を勝手に探す。JSON を直接渡してもよい）。
**先に書くほうが基準である。**

**なぜ必要か。**72 行 216 本の成功率は、**同じ重みを 2 回測るだけで 0.667 と 0.722 の間を
動く。**だから率の差 0.05 は何の証拠にもならない。**同じ `(タスク, エピソード番号)` は
同じ初期状態である**（評価キットは初期状態をファイルから順に読み、乱数を使わない）ので、
**対にして差の符号を数えれば、率では消える差が残る。**

**出るもの。**条件ごとに 2 つの表が出る（条件名は実行ディレクトリに写された
`TASKS_CSV.csv` の `category` と `difficulty_level` から作る）。

| 表 | 中身 | 読み方 |
|---|---|---|
| 成功率の対 | 上がった数・下がった数・同じ数・符号検定の p | **p は「上下が偶然と区別できるか」だけを見る。**条件ごとだとタスクは 12 しかないので、3 対 2 は引き分けである |
| 歩数の対 | 上下の数・中位の変化・p | **両方で 1 回以上成功したタスクだけを見る**（成功 0 の回の歩数は打ち切りの 300 に張り付くので、混ぜると成功率の差を二重に数える） |

**実際の読み取りの例。**8/28 の 1,500 歩は、狙って入れたカメラ条件が
**3 対 2 と 3 対 3 の引き分け**だった——率では合計点 0.3674 → 0.3351 と下がって見えたが、
**下がったと言い切る根拠も無い**（合計 9 対 20・p = 0.061）。

## `score_composite.py` —— 採点式の形に写す

```bash
python3 solution/tools/eval/score_composite.py work/final_eval/<実行>
```

**配布キットの総合スコアは成功率そのものである**（`pipeline/scorer.py:124`）。
運営の式は**成功を掛け算の門にして、なめらかさ 5 項の重み付き和を掛ける。**
この道具はその形を手元で組み直す（重みは 5 等分・正規化は `基準値 /（基準値 + 実測）`）。
**基準値は固定値である**——実行ごとに取り直すと実行間で比べられなくなる。
**書き出す先は実行ディレクトリの `score_composite.md`。**

## 気をつけること

- **`run_final_eval.sh` は `docker run` なので Claude の Bash からは拒否される。**
  ユーザに貼って渡す（[howto/12](../../../docs/howto/12_bring_eval_to_rtx6000.md)）。
- **同じ CSV で回した実行どうしでないと対にできない。**行が違うと
  「同じ名前のタスクが 1 つも無い」で止まる。
- **評価は 1 本 64 分（72 行 216 本・RTX6000）。**2 台で同時に回すと描画で食い合う。
